UNIT III – Relational Database Design and Normalization

1. What is a Functional Dependency?

A functional dependency shows a relationship between two attributes. It means that the value of one attribute can determine the value of another attribute.

Example: Student_ID → Student_Name

Here, Student_ID determines Student_Name because each student ID belongs to only one student.

2. Define Attribute Closure.

Attribute closure is the set of all attributes that can be determined from a given set of attributes using the functional dependencies.

Example:

If A → B and B → C, then the closure of A is:

A+ = {A, B, C}

This means A can determine A, B and C.

3. What is a Minimal Cover?

A minimal cover is the smallest equivalent set of functional dependencies. It contains no unnecessary attributes or dependencies.

Example:

If we have:

A → BC

It can be divided into:

  • A → B
  • A → C

This gives a simpler set of dependencies.

4. What is Decomposition of a Relation?

Decomposition means splitting one large relation or table into two or more smaller tables to reduce redundancy and improve database design.

Example:

A Student table containing Student_ID, Student_Name and Department_Name can be divided into Student and Department tables.

5. What is a Lossless-Join Decomposition?

A decomposition is called lossless-join when the original table can be obtained exactly by joining the smaller tables.

It should not create any extra or incorrect rows.

Example: If a Student table is divided into Student and Department tables, joining them should give back the original Student information correctly.

6. What is Dependency Preservation?

Dependency preservation means that all the important functional dependencies can be checked using the decomposed tables without joining them again.

Example:

If the original table has A → B, after decomposition we should still be able to check A → B using the smaller tables.

7. Define 1NF and 2NF.

1NF (First Normal Form):

A table is in 1NF when every column contains only atomic or single values and there are no repeating groups.

Example: A student should have separate rows for different phone numbers instead of storing multiple numbers in one cell.

2NF (Second Normal Form):

A table must first be in 1NF, and every non-key attribute must depend on the complete primary key.

2NF mainly removes partial dependency.

8. Define 3NF and BCNF.

3NF (Third Normal Form):

A table is in 3NF when it is in 2NF and non-key attributes do not depend on other non-key attributes.

BCNF (Boyce-Codd Normal Form):

A table is in BCNF when, for every non-trivial functional dependency, the determinant is a superkey.

BCNF is stricter than 3NF.

9. What is a Multivalued Dependency?

A multivalued dependency occurs when one attribute determines multiple independent values of another attribute.

Example:

A student may have many hobbies and many languages.

Student →→ Hobby

Student →→ Language

The hobbies and languages are independent of each other.

10. What are Insertion, Deletion and Update Anomalies?

Anomalies are problems that occur in a poorly designed database because the same information is stored repeatedly.

  • Insertion anomaly: Difficulty in adding new information.
  • Deletion anomaly: Deleting one record may accidentally remove useful information.
  • Update anomaly: The same information must be changed in many places.
Example: If a department name is repeated in many student rows, changing the department name requires updating many rows.

UNIT IV – Transactions

11. What is a Transaction?

A transaction is a sequence of database operations treated as one logical unit of work.

A transaction should either complete successfully or should not affect the database.

Example: Transferring ₹500 from Account A to Account B involves deducting ₹500 from A and adding ₹500 to B.

12. What are the Four ACID Properties?

ACID properties ensure that database transactions are reliable.

  • Atomicity: All operations happen or none happen.
  • Consistency: The database remains correct after the transaction.
  • Isolation: Transactions do not interfere with each other.
  • Durability: Completed changes remain saved even after a failure.
Example: During a bank transfer, money should be deducted from one account and added to another. Both operations must happen correctly.

13. What is a Schedule?

A schedule is the order in which the operations of one or more transactions are executed.

Example:

T1: Read(A) → Write(A)

T2: Read(B) → Write(B)

The order of these operations forms a schedule.

14. Differentiate between Serial and Non-Serial Schedules.

Serial Schedule:

One transaction completes completely before another transaction starts.

Non-Serial Schedule:

Operations of different transactions can be mixed or interleaved.

Example:
Serial: T1 → T2
Non-Serial: T1 → T2 → T1 → T2

15. What is Serializability?

Serializability is the property that allows a non-serial schedule to produce the same result as some serial schedule.

It helps maintain the correctness of the database when transactions run at the same time.

Example: If a non-serial schedule gives the same result as T1 followed by T2, it is considered serializable.

16. What is Conflict Serializability?

Conflict serializability checks whether a schedule can be converted into a serial schedule by changing the order of non-conflicting operations.

A precedence graph is commonly used to check conflict serializability. If the graph has no cycle, the schedule is conflict serializable.

Example: If T1 and T2 perform operations that do not create a cycle in the precedence graph, the schedule is conflict serializable.

17. What is Concurrency Control?

Concurrency control is the process of managing multiple transactions running at the same time.

It prevents incorrect results and maintains database consistency.

Example: Two users trying to update the same bank account at the same time must be controlled properly.

18. What are Shared and Exclusive Locks?

Locks are used to control access to database data when multiple transactions are running.

  • Shared Lock (S): Used for reading data. Multiple transactions can usually hold a shared lock at the same time.
  • Exclusive Lock (X): Used for writing or modifying data. Other transactions cannot access the locked data in a conflicting way.
Example: T1 reads Account A → Shared Lock.
T2 wants to update Account A → Exclusive Lock.

19. What is Two-Phase Locking (2PL)?

Two-Phase Locking is a concurrency control method that uses two phases to control locks.

  • Growing Phase: The transaction can acquire locks but cannot release them.
  • Shrinking Phase: The transaction can release locks but cannot acquire new locks.
Example: First, a transaction obtains all required locks. After that, it starts releasing the locks.

20. What is a Deadlock? Mention any Two Methods for Handling It.

A deadlock occurs when two or more transactions wait for each other indefinitely and none of them can continue.

Methods for handling deadlock:

  • Deadlock prevention
  • Deadlock detection and recovery
Example: T1 holds a lock on A and waits for B, while T2 holds B and waits for A. Both transactions keep waiting.

UNIT V – Storage, Indexing, Query Processing and Emerging Trends

21. What is File Organization?

File organization is the method used to arrange and store records in a database file.

Main types include:

  • Heap file organization
  • Sequential or sorted file organization
  • Hash file organization
Example: Student records can be stored based on Student_ID or simply in the order in which they are inserted.

22. What is Heap File Organization?

Heap file organization stores records in no particular order. New records are generally placed wherever space is available.

It is simple and makes insertion fast, but searching for a particular record can be slow.

Example: Student records are inserted one after another without arranging them by Student_ID.

23. What is Indexing?

Indexing is a technique used to make searching and retrieving records from a database faster.

An index works like an index in a book, helping the database quickly find the required data.

Example: An index on Student_ID helps the database quickly find a student with Student_ID = 105.

24. Differentiate between Single-Level and Multi-Level Indexing.

Single-Level Indexing:

It has one level of index entries that directly point to the data records.

Multi-Level Indexing:

It uses multiple levels of indexes, where one index can point to another index. This is useful when the index itself becomes large.

Example: A small table may use a single-level index, while a very large table may use multiple index levels for faster searching.

25. What is a Clustered Index?

A clustered index organizes the stored records according to the indexed field or key.

The data records are arranged in the same general order as the index.

Example: If Student_ID is used as the clustered index, student records can be stored in Student_ID order.

26. What is a B+ Tree?

A B+ tree is a balanced tree data structure commonly used for database indexing.

It keeps the data entries at the leaf level, and the leaf nodes are linked to make sequential searching easier.

Example: A database can use a B+ tree index on Student_ID to quickly find students with IDs between 100 and 200.

27. What is Hash Indexing?

Hash indexing uses a hash function to convert a search key into a location called a bucket.

It is especially useful for quickly finding records using exact values.

Example: Searching for Student_ID = 105 can use a hash function to directly locate the bucket containing student 105.

28. What are the Main Steps in Query Processing?

Query processing is the process of converting a user's SQL query into a form that the database can execute efficiently.

Main steps:

  1. Parsing and validation
  2. Translation of the query
  3. Query optimization
  4. Selection of an execution plan
  5. Query execution
Example: For SELECT * FROM Student WHERE Student_ID = 105;, the DBMS checks the query, finds an efficient way to search, and then returns the required student record.

29. What is Query Optimization? What is Cost-Based Optimization?

Query Optimization is the process of choosing an efficient way to execute a SQL query.

Cost-Based Optimization compares different possible execution plans and chooses the plan with the lowest estimated cost.

Example: If a table has an index on Student_ID, the optimizer may choose the index instead of scanning the entire table because it is faster.

30. What is NoSQL? Mention the Major Types of NoSQL Databases.

NoSQL means "Not Only SQL". It refers to databases that use flexible data models and are useful for large-scale or rapidly changing data.

Major types of NoSQL databases:

  • Key-Value Database
  • Document Database
  • Column-Family Database
  • Graph Database
Example: A document database can store a student's information as a flexible document containing name, age, department and subjects.

1. Define Normalization. Explain its need and types.

Definition

Normalization is the process of organizing data in a database to reduce data redundancy (unnecessary repetition) and avoid data anomalies.

In simple words, normalization means dividing a large table into smaller, related tables so that data is stored properly without unnecessary duplication.

Example of an unnormalized table

Student_ID Student_Name Department Subjects
101 Arun CSE DBMS, Java, OS
102 Priya CSE DBMS, Java
103 Rahul ECE DBMS, Networks

Here, multiple subjects are stored in one column. This creates problems when we search, update, or delete data.

After normalization:

Student Table

102 Priya D01
103 Rahul D02

Department Table

Dept_ID Dept_Name
D01 CSE
D02 ECE

Student_Subject Table

Student_ID Subject

Now the data is organized properly.

Need for Normalization

Normalization is required for the following reasons:

1. Reduces Data Redundancy

Redundancy means storing the same information repeatedly.

For example:

Student Department HOD
Arun CSE Kumar
Priya CSE Kumar
Rahul CSE Kumar

The HOD name Kumar is repeated many times.

Normalization stores department information separately.

2. Avoids Update Anomaly

An update anomaly occurs when the same information exists in many places and we must update it everywhere.

Example:

If the CSE HOD changes from Kumar to Ravi, every row must be updated.

If one row is forgotten, inconsistent data occurs.

Normalization stores it only once.

3. Avoids Insertion Anomaly

An insertion anomaly occurs when we cannot insert information because some unrelated information is missing.

Example:

We want to add a new department:

AI & DS

But if the table requires a student ID, we cannot add the department until a student exists.

Separating the Department table solves this problem.

4. Avoids Deletion Anomaly

A deletion anomaly occurs when deleting one piece of information accidentally removes another important piece.

Example:

If the only student belonging to the ECE department is deleted, the department information may also disappear.

Separate tables prevent this problem.

Types / Normal Forms

Normalization is divided into different normal forms.

The major normal forms are:

  1. First Normal Form – 1NF
  2. Second Normal Form – 2NF
  3. Third Normal Form – 3NF
  4. Boyce-Codd Normal Form – BCNF
  5. Fourth Normal Form – 4NF
  6. Fifth Normal Form – 5NF

1NF – First Normal Form

A table is in 1NF when:

  • Each column contains atomic/single values.
  • There are no repeating groups.
  • Each row is unique.

Not in 1NF

Student_ID Name Subjects
101 Arun DBMS, Java, OS

The Subjects column contains multiple values.

In 1NF

Student_ID Name Subject
101 Arun DBMS
101 Arun Java
101 Arun OS

Each cell contains only one value.

2NF – Second Normal Form

A table is in 2NF when:

  • It is already in 1NF.
  • There must be no partial dependency.

Partial dependency occurs when a non-key attribute depends only on part of a composite primary key.

Example

Suppose:

Student_ID + Subject_ID → Marks

But:

Student_ID → Student_Name

Student_Name depends only on Student_ID, not on the complete key.

So we divide the table.

Now it satisfies 2NF.

A table is in 3NF when:

  • It is already in 2NF.
  • There is no transitive dependency.

Example

Student_ID Student_Name Dept_ID Dept_Name
101 Arun D01 CSE

Here:

Student_ID → Dept_ID

and

Dept_ID → Dept_Name

Therefore:

So divide it into:

BCNF – Boyce-Codd Normal Form

BCNF is a stronger version of 3NF.

A relation is in BCNF if every determinant is a candidate key.

In simple words:

Every attribute that determines another attribute must itself be capable of uniquely identifying a record.

BCNF is mainly used when 3NF still allows certain dependency problems.

4NF – Fourth Normal Form

A table is in 4NF when:

  • It is already in BCNF.
  • It has no unwanted multivalued dependencies.

Example:

A student may have multiple:

  • hobbies
  • languages

If both are stored in the same table, unnecessary combinations are created.

Instead, separate them:

Student_Hobby

Arun English

5NF – Fifth Normal Form

5NF deals with join dependency.

A relation is in 5NF when it cannot be further decomposed without losing important information.

It is useful in complex databases where information is represented using multiple relationships.

Advantages of Normalization

  • Reduces data redundancy.
  • Saves storage space.
  • Prevents insertion anomalies.
  • Prevents update anomalies.
  • Prevents deletion anomalies.
  • Improves data consistency.
  • Makes database structure easier to maintain.
  • Improves data integrity.

Disadvantages

  • Creates more tables.
  • More tables may require more JOIN operations.
  • Complex queries may become slower.
  • Database design can become more complicated at higher normal forms.

Conclusion

Normalization is an important database design technique that organizes data into properly related tables. It reduces duplication and prevents anomalies while maintaining consistency and integrity.

2. Explain Two-Phase Locking with a suitable transaction schedule and show how it ensures serializability.

Introduction

Two-Phase Locking (2PL) is a concurrency-control technique used in DBMS.

It controls simultaneous transactions by using locks.

The main purpose is to ensure that transactions execute in a way that is conflict-serializable.

Types of Locks

There are two major locks.

1. Shared Lock (S-lock)

Used when a transaction wants to read data.

Several transactions can hold a shared lock on the same data.

Example:

T1: Read(A)

gets:

S(A)

2. Exclusive Lock (X-lock)

Used when a transaction wants to write/update data.

Only one transaction can hold an exclusive lock.

Example:

T1: Write(A)

gets:

X(A)

Two Phases of 2PL

2PL contains two phases:

Phase 1 – Growing Phase

During this phase:

  • Transaction can acquire locks.
  • Transaction cannot release locks.

Example:

Lock-S(A)

Lock-X(B)

Phase 2 – Shrinking Phase

During this phase:

  • Transaction releases locks.
  • Transaction cannot acquire any new lock.

Example:

Unlock(A)

Unlock(B)

Important rule

Once a transaction releases its first lock, it cannot acquire another lock.

Example

Consider two transactions.

T1

Lock-X(A)
Read(A)
Write(A)

Lock-X(B)
Read(B)
Write(B)

Unlock(A)
Unlock(B)

T2

Lock-S(A)
Read(A)
Unlock(A)

T1 first obtains the required locks.

After T1 starts releasing locks, it cannot obtain any new lock.

Therefore, it follows two-phase locking.

How 2PL Ensures Serializability

Consider:

T1: Lock-X(A)
T1: Write(A)
T1: Unlock(A)

T2: Lock-S(A)
T2: Read(A)
T2: Unlock(A)

T2 can access A only after T1 releases it.

Therefore, the result is equivalent to:

T1 → T2

which is a serial order.

Hence, 2PL guarantees conflict serializability.

Advantages

  • Ensures conflict serializability.
  • Prevents many concurrency problems.
  • Simple and widely used.
  • Maintains database consistency.

Disadvantages

  • Can cause deadlock.
  • Transactions may have to wait.
  • Reduces concurrency in some situations.

Conclusion

Two-phase locking divides transaction execution into a growing phase and shrinking phase. By controlling when locks can be acquired and released, it ensures conflict-serializable schedules.

3. Explain ACID properties of database transactions with a suitable real-time banking example.

A transaction is a group of database operations treated as one logical unit.

For example, transferring ₹5,000 from Account A to Account B involves:

Debit ₹5,000 from A
Credit ₹5,000 to B

Both operations should happen correctly.

ACID stands for:

A – Atomicity
C – Consistency
I – Isolation
D – Durability

1. Atomicity

Atomicity means:

A transaction is treated as one complete unit. Either all operations happen or none happen.

Banking example

Suppose:

A = ₹10,000
B = ₹5,000

Transfer ₹2,000:

A = A - 2000
B = B + 2000

If money is deducted from A but the system crashes before adding it to B, the transaction must be rolled back.

Final result:

A = ₹10,000
B = ₹5,000

Therefore, partial transactions are not allowed.

2. Consistency

Consistency means:

A transaction must take the database from one valid state to another valid state.

Example:

Before transfer:

A + B = ₹15,000

After transferring ₹2,000:

A + B = ₹15,000

The total amount remains the same.

Therefore, database rules are preserved.

3. Isolation

Isolation means:

Multiple transactions executing at the same time should not interfere with each other.

Example:

Two transactions simultaneously try to withdraw money from the same account.

The database ensures that one transaction does not see incomplete changes made by another transaction.

4. Durability

Durability means:

Once a transaction is successfully committed, its changes are permanently stored.

Example:

You transfer ₹2,000 and receive:

Transaction Successful

Even if the database server crashes immediately afterward, the transaction should not disappear.

Real-Time Example

ATM withdrawal:

1. Check account balance
2. Deduct amount
3. Dispense cash
4. Update account
5. Commit transaction

ACID properties ensure that this process happens safely.

Conclusion

ACID properties provide reliability and correctness in database transactions. They are especially important in banking, e-commerce, reservation systems and other systems where incorrect data can cause serious problems.

5. Explain serial and non-serial schedules with examples. Analyze the given schedule using a precedence graph to determine conflict serializability.

Schedule

A schedule is the order in which operations of multiple transactions are executed.

Serial Schedule

In a serial schedule, one transaction completely finishes before another transaction starts.

Example:

T1: Read(A)
T1: Write(A)
T1: Read(B)
T1: Write(B)

T2: Read(A)
T2: Write(A)

Order:

T1 → T2

There is no interleaving.

Advantage

Very safe and easy to understand.

Disadvantage

Less concurrency and lower performance.

Non-Serial Schedule

In a non-serial schedule, operations of different transactions are interleaved.

Example:

T1: Read(A)
T2: Read(B)
T1: Write(A)
T2: Write(B)

Here operations of T1 and T2 are mixed.

Non-serial schedules provide better concurrency.

Conflict Operations

Two operations conflict when:

  1. They belong to different transactions.
  2. They operate on the same data item.
  3. At least one operation is a WRITE.

Examples:

R1(A) and W2(A) → Conflict
W1(A) and R2(A) → Conflict
W1(A) and W2(A) → Conflict

But:

R1(A) and R2(A)

do not conflict.

Precedence Graph

A precedence graph is used to determine whether a schedule is conflict serializable.

Steps

  1. Create one node for every transaction.
  2. Look for conflicting operations.
  3. If Ti's operation occurs before Tj's conflicting operation, draw:
Ti → Tj
  1. Check the graph for cycles.

Rule

No cycle → Conflict serializable

Cycle → Not conflict serializable

Example

Consider:

R1(A)
W1(A)
R2(A)
W2(A)

Conflicts create:

T1 → T2

Graph:

T1 ─────→ T2

There is no cycle.

Therefore, Schedule is conflict serializable.

Equivalent serial order:

T1 → T2

Example with a cycle

Suppose:

R1(A)
R2(B)
W1(B)
W2(A)

Conflicts produce:

T1 → T2
T2 → T1

Graph:

      ┌───────┐
      ↓       |
     T1 ←──── T2

There is a cycle.

Therefore:

Schedule is NOT conflict serializable.

8. Explain the need for concurrency control in DBMS.

Definition

Concurrency control is the process of managing multiple transactions executing at the same time without causing incorrect or inconsistent data.

In a real database, thousands of users may access the same data simultaneously.

For example:

User A → Withdraw ₹5,000
User B → Withdraw ₹3,000

Both may access the same account simultaneously.

Without concurrency control, incorrect results can occur.

Need for Concurrency Control

1. Lost Update Problem

Two transactions read the same value and update it.

Example:

Initial balance:

₹10,000

T1 reads ₹10,000.

T2 also reads ₹10,000.

T1 withdraws ₹2,000:

₹8,000

T2 withdraws ₹3,000:

₹7,000

One update may overwrite another.

This is called lost update.

2. Dirty Read

A transaction reads data that another transaction has modified but not committed.

Example:

T1 changes A = 5000
T2 reads A = 5000
T1 rolls back

Now T2 has read incorrect/uncommitted data.

3. Non-Repeatable Read

A transaction reads the same data twice but gets different values.

Example:

T1 reads A = 1000
T2 updates A = 2000
T1 reads A again = 2000

The same transaction received different values.

4. Incorrect Summary

Suppose T1 calculates total bank balance while T2 is updating accounts.

T1 may calculate using a mixture of old and new values.

Therefore, the result becomes incorrect.

Concurrency Control Techniques

1. Lock-Based Protocol

Uses locks.

Examples:

  • Shared lock
  • Exclusive lock
  • Two-phase locking

2. Timestamp-Based Protocol

Each transaction receives a timestamp.

The DBMS uses timestamps to determine the correct order of operations.

3. Optimistic Concurrency Control

Transactions execute without locking initially.

Before committing, the system checks whether conflicts occurred.

4. Multiversion Concurrency Control

Multiple versions of data are maintained.

Readers can access an appropriate version without blocking writers.

Advantages

Concurrency control:

  • Maintains consistency.
  • Prevents data corruption.
  • Prevents lost updates.
  • Controls conflicting transactions.
  • Improves database reliability.
  • Allows multiple users to work simultaneously.

Conclusion

Concurrency control is essential in multi-user DBMS environments. It allows transactions to execute concurrently while ensuring that the final database state remains correct and consistent.

9. Explain the structure and properties of a B+ Tree for a given set of keys. Illustrate searching, insertion and splitting with example.

Definition

A B+ Tree is a balanced tree data structure commonly used in DBMS indexing.

It is especially useful for:

  • Searching records
  • Range queries
  • Database indexing
  • File systems

Structure of B+ Tree

A B+ Tree has:

  1. Root node
  2. Internal nodes
  3. Leaf nodes

Important feature

Actual data/record pointers are stored only in leaf nodes.

Internal nodes mainly contain keys and pointers to child nodes.

Leaf nodes are connected using linked pointers.

Example:

              [30 | 60]
             /    |     \
            /     |      \
       [10,20] [30,40,50] [60,70,80]
          ↔          ↔           ↔

The leaf nodes are linked for fast sequential/range searching.

Properties of B+ Tree

  • It is always balanced.
  • All leaf nodes are at the same level.
  • Internal nodes contain keys and child pointers.
  • Leaf nodes contain keys and record pointers.
  • Leaf nodes are linked together.
  • Searching is efficient.
  • Supports range queries efficiently.
  • Height remains small even for large data.

Searching

Suppose the tree is:

             [30 | 60]
            /    |     \
           /     |      \
      [10,20] [30,40,50] [60,70,80]

Search for:

50

Step 1

Start from root:

[30 | 60]

50 lies between 30 and 60.

Move to middle child.

Step 2

Search:

[30,40,50]

50 is found.

Thus B+ Tree provides fast searching.

Insertion

Suppose we insert:

25

Current leaf:

[10,20]

After insertion:

[10,20,25]

If the node exceeds its maximum capacity, it must be split.

Splitting

Suppose a leaf can contain a maximum of 3 keys.

If we insert 30:

[10,20,25,30]

This exceeds the limit.

Split it:

[10,20]    [25,30]

The first key of the new right node is copied to the parent.

Parent becomes:

[25 | 60]

So:

              [25 | 60]
             /    |     \
        [10,20] [25,30] [60,70,80]

The leaf nodes remain linked.

Advantages of B+ Tree

  • Very fast searching.
  • Efficient insertion and deletion.
  • Excellent for range queries.
  • Always balanced.
  • Suitable for large databases.
  • Reduces disk I/O.
  • Leaf nodes allow sequential access.

Real-time example

Suppose a college database contains:

1,00,000 student records

An index on:

Student_ID

can use a B+ Tree.

Instead of checking every student record, the DBMS follows the tree and quickly reaches the required record.

B+ Tree vs B Tree

B Tree B+ Tree
Records may be stored in internal and leaf nodes Records are stored at leaf level
Leaf nodes may not be linked Leaf nodes are linked
Sequential search is less efficient Range/sequential search is efficient
Used for indexing Very commonly used for DBMS indexing

Conclusion

B+ Trees are important indexing structures in DBMS because they provide fast searching, insertion, deletion and especially efficient range queries.

10. Explain the need for NoSQL databases. Discuss Key-Value Store and Document Store.

Definition

NoSQL means “Not Only SQL.”

NoSQL databases are non-relational databases designed to handle:

  • Large amounts of data
  • Unstructured/semi-structured data
  • High-speed operations
  • Distributed systems
  • Flexible data structures

Need for NoSQL

Traditional relational databases use tables with fixed schemas.

But modern applications often generate huge amounts of data.

Examples:

  • Social media
  • Online shopping
  • IoT
  • Gaming
  • Real-time applications
  • Big-data applications

The structure of this data may change frequently.

NoSQL databases provide greater flexibility.

Advantages of NoSQL

1. Flexible Schema

The structure can change easily.

For example:

{
   "name": "Arun",
   "age": 20
}

Later, we can add:

"skills": ["JavaScript", "Python"]

without redesigning a fixed table.

2. High Scalability

NoSQL databases can scale horizontally by adding more servers.

3. High Performance

They are suitable for applications requiring fast read/write operations.

4. Handles Large Data

NoSQL is suitable for very large datasets.

5. Suitable for Distributed Systems

NoSQL databases are designed to work across multiple servers.

Types of NoSQL Databases

The major types are:

  1. Key-Value Store
  2. Document Store
  3. Column-Family Store
  4. Graph Database

1. Key-Value Store

Data is stored as:

Key → Value

Example:

101 → "Arun"
102 → "Priya"
103 → "Rahul"

The key uniquely identifies the value.

Example

user:101 → Arun
user:102 → Priya

Real-time uses

Key-value stores are useful for:

  • Caching
  • Session management
  • Shopping carts
  • User preferences
  • Fast lookups

Example database

Redis

2. Document Store

Data is stored as documents, usually in JSON/BSON-like format.

Example:

{
   "student_id": 101,
   "name": "Arun",
   "department": "CSE",
   "skills": ["Java", "Python"]
}

Another document can have a different structure:

{
   "student_id": 102,
   "name": "Priya",
   "department": "ECE",
   "phone": "9876543210"
}

The schema is flexible.

Example database

MongoDB

3. Column-Family Store

Data is organized using column families instead of traditional relational tables.

Examples:

  • Apache Cassandra
  • HBase

Useful for:

  • Big data
  • Analytics
  • Distributed systems

4. Graph Database

Data is represented using:

  • Nodes
  • Relationships
  • Properties

Example:

Arun ──FRIEND_OF──→ Priya
  |
  |
STUDIES
  ↓
CSE

Useful for:

  • Social networks
  • Recommendation systems
  • Fraud detection
  • Relationship-based applications

Example:

Neo4j

Key-Value vs Document Store

Feature Key-Value Document
Structure Key → Value JSON/BSON document
Schema Flexible Flexible
Access Mainly by key By fields/contents
Example Redis MongoDB
Best for Fast lookup/cache Complex application data
Data Simple Rich/structured documents

When to Use NoSQL?

Use NoSQL when:

  • Data structure changes frequently.
  • Very large amounts of data are generated.
  • High performance is required.
  • Horizontal scalability is required.
  • Data is semi-structured or unstructured.
  • Distributed applications are required.

Conclusion

NoSQL databases provide flexibility, scalability and high performance for modern applications. Key-value databases are ideal for simple and extremely fast lookups, while document databases such as MongoDB are suitable for flexible, JSON-like application data.
