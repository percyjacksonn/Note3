1. Define a microprocessor.

A microprocessor is a programmable electronic device that acts as the CPU of a computer system. It performs arithmetic, logical and control operations based on instructions given to it.

2. Define a microcontroller.

A microcontroller is a single-chip computer that contains a CPU, memory (RAM and ROM) and input/output (I/O) ports. It is mainly used in embedded systems.

4. Define an interrupt.

An interrupt is a signal that temporarily stops the normal execution of a program and makes the processor execute a special routine called the Interrupt Service Routine (ISR).

5. What is the function of the Program Counter?

The Program Counter (PC) is a special register that stores the address of the next instruction to be executed by the processor.

6. What is the function of the Stack Pointer?

The Stack Pointer (SP) is a special register that holds the address of the top of the stack in memory. It is used during subroutine calls, returns and interrupt handling.

7. Define an opcode and an operand.

  • Opcode: Specifies the operation to be performed by the processor.
  • Operand: Specifies the data or address on which the operation is performed.

Example: In ADD A, B, ADD is the opcode and A, B are the operands.

8. What is meant by instruction execution cycle?

The instruction execution cycle is the sequence of steps performed by a processor to execute an instruction.

It consists of three main stages:

  1. Fetch: Retrieves the instruction from memory.
  2. Decode: Identifies the operation to be performed.
  3. Execute: Performs the specified operation.

2. Explain the various registers, ALU, control unit and flag register of the 8085 microprocessor.

Registers are small, high-speed storage locations inside the microprocessor. They temporarily store data, addresses and instructions during program execution.

Accumulator: An 8-bit register used to store operands and results of ALU operations.

General-purpose registers: B, C, D, E, H and L are six 8-bit registers. They can be combined as BC, DE and HL 16-bit pairs.

Program Counter: Stores the address of the next instruction to be executed.

Stack Pointer: Points to the top of the stack and is used during PUSH, POP, CALL and RET operations.

Instruction Register: Temporarily stores the opcode fetched from memory.

ALU: Performs arithmetic and logical operations on data.

Control Unit: Decodes instructions and generates control and timing signals to coordinate the processor's operations.

Flag Register: Contains five condition flags that indicate the result of operations.

3. Explain the different addressing modes of the 8085 microprocessor with suitable examples.

An addressing mode specifies how an instruction identifies the operand on which it operates.

  1. Immediate addressing: The data is included directly in the instruction. Example: MVI A,32H loads 32H into A.
  2. Register addressing: The operand is present in a register. Example: MOV A,B copies the contents of B into A.
  3. Direct addressing: The instruction contains the memory address. Example: LDA 2050H loads A from memory location 2050H.
  4. Register indirect addressing: A register pair contains the memory address. Example: MOV A,M reads the memory byte addressed by HL. LDAX B reads from the address in BC.
  5. Implied addressing: The operand is understood from the instruction itself. Example: CMA complements the accumulator.
Important: In 8085, M represents the memory location whose address is stored in the HL register pair.

7. Explain the evolution of microprocessor architectures and discuss the features of 8-bit microprocessors.

Microprocessor architecture has evolved with improvements in semiconductor technology. Each generation introduced wider data paths, higher processing speeds, larger memory capacity and more advanced instructions.

  1. 4-bit microprocessors: Early processors mainly used in calculators and simple electronic devices.
  2. 8-bit microprocessors: Examples include Intel 8085, Zilog Z80 and MOS 6502. They were used in early computers and control systems.
  3. 16-bit microprocessors: Examples include Intel 8086 and 80286. They support wider data processing and larger address spaces.
  4. 32-bit microprocessors: Provide wider registers and address capabilities for personal computers and embedded applications.
  5. 64-bit microprocessors: Used in modern computers and mobile devices, supporting large address spaces and advanced processing.
  6. Modern architectures: Include multicore processing, cache memory, pipelining, power management and specialized processing units.

Features of 8-bit microprocessors:

  • Process 8 bits of data at a time.
  • Contain an ALU, registers, instruction decoder and control unit.
  • Support arithmetic, logical, data-transfer and branching instructions.
  • Usually use an 8-bit data bus, although address-bus width varies by processor.
  • Suitable for simple control, measurement and embedded applications.
Example: The 8085 is an 8-bit microprocessor with a 16-bit address bus. It can address 64 KB of memory. The 8-bit description refers to its data width, not its address width.

2. Describe the segmented memory organization of 8086 with suitable examples.

The 8086 uses segmented memory organization. Memory is divided into logical segments, each of which can contain up to 64 KB.

The four main segments are:

  1. Code Segment (CS): Stores program instructions.
  2. Data Segment (DS): Stores data used by the program.
  3. Stack Segment (SS): Stores stack data, return addresses and temporary values.
  4. Extra Segment (ES): Provides an additional data segment, commonly used in string operations.

The physical address is calculated using the segment address and offset:

Physical Address = Segment × 10H + Offset

Example:

Segment = 2000H
Offset = 1500H

Physical Address
= 2000H × 10H + 1500H
= 20000H + 1500H
= 21500H

Thus, the physical memory address is 21500H.

Advantages: Allows organized memory management, separates code and data, supports stack operations and provides access to the 1 MB address space.

4. Explain the different addressing modes of 8086 with suitable examples.

Addressing modes specify how the 8086 accesses operands.

  1. Immediate: Operand is part of the instruction. Example: MOV AX,1234H.
  2. Register: Operand is in a register. Example: MOV AX,BX.
  3. Direct memory: Instruction specifies the memory offset. Example: MOV AL,[2000H].
  4. Register indirect: A register holds the memory offset. Example: MOV AX,[BX].
  5. Based: Effective address uses BX or BP, optionally with displacement. Example: MOV AX,[BX+04H].
  6. Indexed: Effective address uses SI or DI, optionally with displacement. Example: MOV AX,[SI+08H].
  7. Based-indexed: Combines a base register and index register. Example: MOV AX,[BX+SI].
  8. Relative: A branch target is calculated relative to the instruction pointer. Example: JNZ NEXT.
  9. Implied: Operand is understood from the instruction. Example: CLC.

UNIT I – 8085 MICROPROCESSOR

1. What is a microprocessor? Explain the architecture of 8085.

A microprocessor is a programmable electronic chip that performs arithmetic, logical, control and data-processing operations. It acts as the Central Processing Unit (CPU) of a computer system.

8085 Architecture:

  • ALU: Performs arithmetic and logical operations such as addition, subtraction, AND and OR.
  • Accumulator: An 8-bit register that stores operands and results of ALU operations.
  • General-purpose registers: B, C, D, E, H and L are 8-bit registers. They can also form register pairs BC, DE and HL.
  • Program Counter: A 16-bit register that stores the address of the next instruction.
  • Stack Pointer: A 16-bit register that points to the top of the stack.
  • Instruction Register and Decoder: Holds and decodes the instruction being executed.
  • Timing and Control Unit: Generates signals to control the operations of the microprocessor.
  • Interrupt Control: Handles interrupt requests from external devices.
  • Address and Data Buses: Transfer addresses and data between the processor and other components.
Important points:
  • 8085 is an 8-bit microprocessor.
  • It has a 16-bit address bus.
  • It can address 64 KB of memory.
  • It has an 8-bit data bus.
  • It operates using a single +5 V power supply.

2. Explain the register organization of 8085.

Registers are small, high-speed storage locations inside the microprocessor. They temporarily store data, addresses and intermediate results.

  • Accumulator (A): Stores data used in arithmetic and logical operations.
  • B and C: General-purpose 8-bit registers.
  • D and E: General-purpose 8-bit registers.
  • H and L: General-purpose registers that can form the HL register pair, often used to hold a memory address.
  • Program Counter (PC): Stores the address of the next instruction.
  • Stack Pointer (SP): Stores the address of the top of the stack.
  • Flag Register: Stores the status of the result of an operation.

Register pairs:

BC, DE and HL can be used as 16-bit register pairs. The accumulator and flag register together form the Program Status Word (PSW).

Remember: The accumulator is 8-bit, while PC and SP are 16-bit registers.

3. Explain the flag register of 8085.

The flag register is an 8-bit register that indicates the status of the result produced by an arithmetic or logical operation. Five flags are used in the 8085 microprocessor.

Z Zero Flag Set when the result is zero.
AC Auxiliary Carry Set when carry occurs from bit 3 to bit 4.
P Parity Flag Set when the result contains an even number of 1s.
CY Carry Flag Set when a carry or borrow occurs.
Example:

If the result of an operation is 00H, the Zero Flag is set. If the result contains an even number of binary 1s, the Parity Flag is set.

Important: The five flags are Sign, Zero, Auxiliary Carry, Parity and Carry.

An interrupt is a signal that temporarily stops the normal execution of a program and transfers control to a special routine called the Interrupt Service Routine (ISR).

5. Explain the instruction cycle, machine cycle and T-state.

Instruction Cycle: The total time required to fetch and execute one instruction.

Machine Cycle: The time required to complete one basic operation, such as opcode fetch, memory read or memory write.

T-State: The smallest unit of time in a processor operation. One T-state corresponds to one clock period.

Relationship: One instruction cycle may contain one or more machine cycles. Each machine cycle contains multiple T-states.
Example: An 8085 opcode fetch machine cycle normally takes 4 T-states. A typical memory read or memory write machine cycle takes 3 T-states.

UNIT II – 8086 MICROPROCESSOR

1. Explain the architecture of 8086 microprocessor.

The 8086 is a 16-bit microprocessor developed by Intel. Its architecture is divided into two major functional units: the Bus Interface Unit and the Execution Unit.

1. Bus Interface Unit (BIU):

  • Fetches instructions from memory.
  • Reads and writes data from and to memory.
  • Generates the physical address.
  • Contains segment registers and the instruction pointer.
  • Contains a 6-byte instruction queue.

2. Execution Unit (EU):

  • Decodes and executes instructions.
  • Contains the ALU.
  • Contains general-purpose registers.
  • Contains the flag register.
Important points:
  • 8086 is a 16-bit processor.
  • It has a 20-bit address bus.
  • It can address 1 MB of memory.
  • Its data bus is 16-bit wide.
  • Its instruction queue is 6 bytes long.

2. Explain the BIU and EU in detail.

The 8086 processor uses two separate units to improve instruction processing.

Bus Interface Unit:

  • Fetches instructions from memory.
  • Performs bus operations.
  • Calculates physical addresses.
  • Stores prefetched instructions in the queue.

Execution Unit:

  • Receives instructions from the queue.
  • Decodes instructions.
  • Performs arithmetic and logical operations.
  • Controls execution using the control circuitry.
Advantage: While the EU executes an instruction, the BIU can fetch upcoming instructions. This overlapping improves processing efficiency and is called instruction pipelining.

Other registers:

Types of segments:

1. What is a microcontroller? Explain the architecture of 8051.

A microcontroller is a compact integrated circuit that contains a processor, memory and input/output peripherals on a single chip. It is mainly used in embedded systems.

  • Timers/Counters: Two 16-bit timer/counter units.
  • Serial Port: Supports serial communication.
  • Interrupt Control: Handles interrupt requests.
  • Oscillator and Clock Circuit: Provides timing for processor operations.
Important points:
  • 8051 is an 8-bit microcontroller.
  • It has 4 KB on-chip ROM in the classic version.
  • It has 128 bytes of internal RAM.
  • It has 32 programmable I/O lines.
  • It has two 16-bit timers/counters.
  • It has one serial communication port.

The 8051 has separate program memory and data memory spaces.

Program Memory:

  • Stores the instructions of the program.
  • The classic 8051 contains 4 KB of internal ROM.
  • It can also access external program memory.

Data Memory:

  • The classic 8051 contains 128 bytes of internal RAM.
  • RAM stores temporary data and variables.
  • It contains register banks, bit-addressable memory and general-purpose RAM.

Special Function Registers (SFRs):

SFRs control special functions such as timers, serial communication, ports and interrupt operations. In the classic 8051, they occupy the address range 80H to FFH.

Important: Internal RAM and SFRs are different memory areas in the 8051.

The 8051 has four 8-bit I/O ports, namely Port 0, Port 1, Port 2 and Port 3. Each port contains eight pins.

  • Port 1: General-purpose I/O port with internal pull-ups in the classic 8051.
  • Port 2: General-purpose I/O and high-order address bus during external memory access.
  • Port 3: General-purpose I/O with alternate functions such as serial communication, interrupts and external memory control.
Important points:
  • Total I/O lines = 4 × 8 = 32.
  • Port 0 requires external pull-ups for ordinary I/O operation.
  • To use a quasi-bidirectional port pin as an input, write 1 to its port latch first.

The 8051 contains two timer/counter units: Timer 0 and Timer 1. They are used for timing operations and counting external events.

Timer operation:

Counter operation:

Timer modes:

  • Mode 2 – 8-bit auto-reload mode.

Applications:

  • Generating baud rates for serial communication.

UNIT 1 – 8085 MICROPROCESSOR

1. Define a microprocessor. Explain the features of 8085.

A microprocessor is a programmable electronic chip that accepts binary data, processes it according to instructions and produces the required output. It acts as the CPU of a computer system.

Features of 8085:

  • It is an 8-bit microprocessor.
  • It has a 16-bit address bus.
  • It can address 64 KB of memory.
  • It has an 8-bit data bus.
  • It contains 40 pins.
  • It operates using a single +5V power supply.
  • It contains six general-purpose registers: B, C, D, E, H and L.
  • It supports hardware and software interrupts.
  • It contains an ALU, accumulator and flag register.

Conclusion: The 8085 is widely used for learning basic microprocessor architecture and programming.

2. Explain the architecture of 8085 microprocessor.

The 8085 architecture consists of different functional units that work together to execute instructions.

Main functional units:

  1. ALU: Performs arithmetic and logical operations such as addition, subtraction, AND, OR and comparison.
  2. Accumulator: An 8-bit register that stores operands and results of arithmetic and logical operations.
  3. General-purpose registers: B, C, D, E, H and L are used for temporary data storage.
  4. Flag register: Contains five flags: Sign, Zero, Auxiliary Carry, Parity and Carry.
  5. Program Counter: A 16-bit register that stores the address of the next instruction.
  6. Stack Pointer: A 16-bit register that points to the top of the stack.
  7. Instruction Register: Holds the current instruction opcode.
  8. Instruction Decoder: Decodes the instruction and determines the required operation.
  9. Timing and Control Unit: Generates control signals for memory and I/O operations.
  10. Interrupt Control: Handles interrupt requests from external devices.

Working: The processor fetches an instruction from memory, decodes it and executes the required operation. The result is stored in a register or memory location.

3. Explain the register organization of 8085.

Registers are small and fast storage locations inside a microprocessor. They temporarily store data, addresses and instructions.

Types of registers:

  • Accumulator (A): An 8-bit register used for arithmetic and logical operations.
  • General-purpose registers: B, C, D, E, H and L store temporary data.
  • Register pairs: BC, DE and HL can be combined to form 16-bit registers.
  • Program Counter (PC): Stores the address of the next instruction.
  • Stack Pointer (SP): Points to the top of the stack.
  • Flag Register: Stores the status of arithmetic and logical operations.
  • Instruction Register: Holds the opcode of the current instruction.

Example:

MOV A,B

This instruction copies the contents of register B into accumulator A.

4. Explain the addressing modes of 8085 with examples.

Addressing modes specify how an instruction accesses its data or operand.

  1. Immediate Addressing: The data is directly given in the instruction.
    Example: MVI A,25H
  2. Register Addressing: The operand is stored in a register.
    Example: MOV A,B
  3. Direct Addressing: The memory address is directly specified in the instruction.
    Example: LDA 2050H
  4. Register Indirect Addressing: The memory address is stored in a register pair.
    Example: MOV A,M (uses HL as the memory pointer).
  5. Implied Addressing: The operand is understood from the instruction itself.
    Example: CMA

Importance: Addressing modes provide different ways to access data efficiently.

5. Explain the flag register of 8085.

The flag register is an 8-bit register that indicates the status of the result after arithmetic and logical operations. Five bits are used as condition flags.

  • Sign Flag (S): Set when the most significant bit of the result is 1.
  • Zero Flag (Z): Set when the result is zero.
  • Auxiliary Carry (AC): Set when a carry occurs from bit 3 to bit 4.
  • Parity Flag (P): Set when the result contains an even number of 1s.
  • Carry Flag (CY): Set when an addition produces a carry or subtraction requires a borrow.

Example: If the result of an operation is 00H, the Zero flag becomes 1.

Importance: Flags are used by conditional instructions such as JZ, JNZ, JC and JNC.

6. Explain the interrupt structure of 8085.

An interrupt is a signal that temporarily stops the normal execution of a program and transfers control to a special routine called the Interrupt Service Routine (ISR).

Hardware interrupts:

  1. TRAP: Highest-priority interrupt. It is non-maskable and vectored.
  2. RST 7.5: Maskable, vectored and edge-triggered.
  3. RST 6.5: Maskable, vectored and level-triggered.
  4. RST 5.5: Maskable, vectored and level-triggered.
  5. INTR: Maskable and non-vectored interrupt.

Software interrupts: RST 0 to RST 7 are software interrupts.

Advantages:

  • Provides quick response to external events.
  • Reduces continuous polling.
  • Improves processor efficiency.

7. Explain instruction cycle, machine cycle and T-state.

Instruction Cycle: The total time required by the processor to fetch and execute one complete instruction.

Machine Cycle: A part of the instruction cycle required to perform one basic operation such as memory read, memory write or opcode fetch.

T-State: One clock period of the microprocessor. It is the smallest basic timing unit.

Relationship:

  • One instruction cycle contains one or more machine cycles.
  • Each machine cycle contains several T-states.

Example: In 8085, an opcode-fetch machine cycle commonly takes 4 T-states, while a memory-read or memory-write machine cycle commonly takes 3 T-states.

8. Explain the functions of 8085 pins.

The 8085 microprocessor is a 40-pin IC. Its pins are divided into different groups.

  • Address Bus (A8–A15): Carries higher-order address bits.
  • Address/Data Bus (AD0–AD7): Carries lower-order address bits and data.
  • ALE: Address Latch Enable separates the lower address from data.
  • RD̅: Read control signal.
  • WR̅: Write control signal.
  • IO/M̅: Selects memory or I/O operation.
  • READY: Allows the processor to wait for slow devices.
  • HOLD: Used to request control of the buses.
  • HLDA: Hold acknowledgement signal.
  • RESET IN: Resets the processor.
  • TRAP and RST interrupts: Interrupt input signals.
  • SID and SOD: Serial input and serial output.
  • X1 and X2: Clock oscillator connections.

UNIT 2 – 8086 MICROPROCESSOR

1. Explain the architecture of 8086.

The 8086 is a 16-bit microprocessor with a 20-bit address bus and a 16-bit data bus. It can address 1 MB of memory.

The architecture is divided into two major units.

1. Bus Interface Unit (BIU):

  • Fetches instructions from memory.
  • Generates physical addresses.
  • Controls memory and I/O operations.
  • Contains segment registers CS, DS, SS and ES.
  • Contains the Instruction Pointer.
  • Has a 6-byte instruction queue.

2. Execution Unit (EU):

  • Decodes and executes instructions.
  • Contains the Arithmetic Logic Unit.
  • Contains general-purpose registers.
  • Contains pointer and index registers.
  • Contains the FLAGS register.

Working: While the Execution Unit executes instructions, the Bus Interface Unit fetches upcoming instructions. This improves processing speed through pipelining.

2. Explain memory segmentation in 8086.

Memory segmentation is a technique that divides the memory into logical sections called segments. Each segment can have a maximum size of 64 KB.

Types of segments:

  • Code Segment (CS): Stores program instructions.
  • Data Segment (DS): Stores data.
  • Stack Segment (SS): Stores stack information.
  • Extra Segment (ES): Provides additional data storage.

Physical address calculation:

Physical Address = Segment Address × 10H + Offset

Example:

Segment = 2000H, Offset = 1234H

Physical Address = 20000H + 1234H = 21234H.

Advantages:

  • Organizes memory into logical sections.
  • Allows separate code, data and stack areas.
  • Supports addressing of 1 MB memory.

3. Explain the addressing modes of 8086 with examples.

Addressing modes specify how the 8086 accesses operands.

  1. Immediate: MOV AX,1234H
  2. Register: MOV AX,BX
  3. Direct Memory: MOV AL,[2000H]
  4. Register Indirect: MOV AX,[BX]
  5. Based: MOV AX,[BX+04H]
  6. Indexed: MOV AX,[SI+04H]
  7. Based Indexed: MOV AX,[BX+SI]
  8. Based Indexed with Displacement: MOV AX,[BX+SI+10H]
  9. Relative: JNZ LABEL
  10. Implied: CLC

Importance: These modes provide flexible access to registers, memory and immediate data.

4. Explain the register organization of 8086.

The 8086 contains 16-bit registers used for data storage, address calculation and program control.

General-purpose registers:

  • AX: Accumulator register.
  • BX: Base register.
  • CX: Count register.
  • DX: Data register.

Each can be divided into two 8-bit registers. For example, AX contains AH and AL.

Pointer registers:

  • SP – Stack Pointer.
  • BP – Base Pointer.

Index registers:

  • SI – Source Index.
  • DI – Destination Index.

Segment registers: CS, DS, SS and ES.

Other registers: IP and FLAGS.

5. Explain pipelining in 8086 and its advantages.

Pipelining is a technique in which instruction fetching and instruction execution take place simultaneously.

The 8086 uses a 6-byte instruction queue.

Working:

  1. The BIU fetches instructions from memory.
  2. The fetched instructions are stored in the instruction queue.
  3. The EU takes instructions from the queue.
  4. The EU decodes and executes them.
  5. Meanwhile, the BIU fetches the next instructions when the bus is available.

Advantages:

  • Improves processing speed.
  • Reduces instruction-fetch waiting time.
  • Uses processor resources efficiently.
  • Allows instruction fetching and execution to overlap.

Important: A branch or jump can empty the instruction queue because fetching must restart from the new address.

6. Explain minimum mode and maximum mode of 8086.

The 8086 operates in two modes depending on the MN/MX̅ pin.

Minimum Mode:

  • Used in single-processor systems.
  • Control signals are generated directly by 8086.
  • Requires simpler hardware.

Maximum Mode:

  • Used in multiprocessor systems.
  • Uses an external 8288 bus controller.
  • Supports more complex bus-sharing arrangements.
  • Can work with a coprocessor such as 8087.

Difference: Minimum mode is suitable for single-processor systems, while maximum mode is suitable for systems with multiple processors or coprocessors.

7. Explain the flag register of 8086.

The FLAGS register is a 16-bit register that contains status and control flags.

Status flags:

  • CF: Carry flag.
  • PF: Parity flag.
  • AF: Auxiliary Carry flag.
  • ZF: Zero flag.
  • SF: Sign flag.
  • OF: Overflow flag.

Control flags:

  • TF: Trap flag for single-step operation.
  • IF: Interrupt enable flag.
  • DF: Direction flag for string operations.

Example: The CMP instruction updates flags according to the comparison result without storing the subtraction result.

8. Explain memory and I/O addressing in 8086.

Memory Addressing:

The 8086 uses a 20-bit address bus and can access 1 MB of memory. It uses segment and offset values to generate physical addresses.

I/O Addressing:

The 8086 supports a separate I/O address space of up to 64 KB.

Types:

  • Direct I/O: The port address is specified in the instruction. Example: IN AL,80H.
  • Indirect I/O: The port address is stored in DX. Example: OUT DX,AL.

Difference: Memory-mapped I/O uses memory addresses and memory instructions. Isolated I/O uses IN and OUT instructions.

UNIT 3 – 8051 MICROCONTROLLER

1. Define a microcontroller. Explain the features of 8051.

A microcontroller is an integrated circuit containing a CPU, memory and input/output peripherals on a single chip. It is mainly used in embedded systems.

Features of classic 8051:

  • 8-bit microcontroller.
  • 4 KB on-chip program ROM.
  • 128 bytes internal RAM.
  • Four 8-bit I/O ports.
  • 32 programmable I/O pins.
  • Two 16-bit timers/counters.
  • Full-duplex serial communication.
  • Five interrupt sources.
  • On-chip oscillator and clock circuit.

Applications: Home appliances, embedded systems, automation and control devices.

Note: These specifications refer to the classic 8051. Modern 8051-compatible devices may have different memory sizes and peripherals.

2. Explain the architecture of 8051 microcontroller.

The 8051 architecture combines the processor, memory and peripherals in a single integrated circuit.

Main components:

  1. CPU: Controls all operations.
  2. ALU: Performs arithmetic and logical operations.
  3. Accumulator: Stores data and operation results.
  4. B Register: Used in multiplication and division operations.
  5. Program Status Word: Contains status flags and register-bank selection bits.
  6. RAM: Stores temporary data.
  7. ROM: Stores the program.
  8. I/O Ports: Connect external devices.
  9. Timers: Generate delays and count external events.
  10. Serial Port: Supports serial communication.
  11. Interrupt Controller: Handles interrupt requests.

Working: The CPU executes instructions stored in program memory and controls connected devices through I/O ports.

3. Explain the memory organization of 8051.

The classic 8051 has separate program and data memory spaces.

Program Memory:

  • Contains 4 KB on-chip ROM in the classic 8051.
  • Stores the program instructions.
  • Can support external program memory.

Data Memory:

  • Contains 128 bytes of internal RAM.
  • Addresses 00H to 1FH are used for four register banks.
  • Addresses 20H to 2FH form the bit-addressable area.
  • Addresses 30H to 7FH are general-purpose RAM.
  • Addresses 80H to FFH are used for Special Function Registers (SFRs).

Importance: Memory organization helps the microcontroller store program instructions, temporary data and control information.

4. Explain the I/O ports of 8051.

The 8051 contains four 8-bit I/O ports: P0, P1, P2 and P3. Together, they provide 32 I/O pins.

  • Port 0: Open-drain port. External pull-up resistors are required when used as general-purpose I/O. It also acts as a multiplexed address/data bus during external memory access.
  • Port 1: General-purpose input/output port.
  • Port 2: General-purpose I/O and higher-order address bus during external memory access.
  • Port 3: Provides alternate functions such as serial communication, external interrupts, timer inputs and external memory control.

Example:

SETB P1.0
CLR P1.0

SETB makes P1.0 high and CLR makes P1.0 low.

Important: Write 1 to a port latch before using a port pin as an input.

5. Explain timers and counters in 8051.

The classic 8051 contains two 16-bit timers/counters called Timer 0 and Timer 1.

Timer Mode: The timer increments using internal machine-cycle timing and is used to generate delays.

Counter Mode: The counter increments when external pulses are received at the T0 or T1 input.

Important registers:

  • TMOD: Selects timer mode and operating mode.
  • TCON: Contains timer control bits and overflow flags.
  • TH0 and TL0: Timer 0 high and low bytes.
  • TH1 and TL1: Timer 1 high and low bytes.

Applications:

  • Generating time delays.
  • Counting external events.
  • Measuring time intervals.
  • Generating serial communication baud rates.

6. Explain serial communication in 8051.

Serial communication is a method of transferring data one bit at a time between two devices.

The 8051 contains a full-duplex serial port.

Important components:

  • TXD: Transmits serial data through P3.1.
  • RXD: Receives serial data through P3.0.
  • SBUF: Serial buffer register.
  • SCON: Serial control register.
  • Timer 1: Commonly used for baud-rate generation in classic 8051 systems.

Working: Data written to SBUF is transmitted through TXD. Incoming data is received through RXD and made available through SBUF.

Applications: Communication with computers, sensors and other microcontrollers.

7. Explain the interrupt structure of 8051.

An interrupt is a signal that temporarily stops normal program execution and transfers control to an Interrupt Service Routine.

Five interrupt sources of classic 8051:

  1. External Interrupt 0 (INT0).
  2. Timer 0 overflow interrupt.
  3. External Interrupt 1 (INT1).
  4. Timer 1 overflow interrupt.
  5. Serial communication interrupt.

Interrupt registers:

  • IE: Interrupt Enable register.
  • IP: Interrupt Priority register.
  • TCON: Contains external interrupt and timer flags.
  • SCON: Contains serial interrupt flags.

Advantages: Interrupts improve response time and avoid unnecessary continuous checking of devices.

8. Explain register banks in 8051.

The 8051 contains four register banks. Each bank has eight registers, R0 to R7.

  • Bank 0: 00H–07H.
  • Bank 1: 08H–0FH.
  • Bank 2: 10H–17H.
  • Bank 3: 18H–1FH.

The active register bank is selected using RS1 and RS0 bits in the PSW register.

Advantages:

  • Provides quick data storage.
  • Reduces the need for repeated memory access.
  • Helps in interrupt handling.

9. Explain the PSW register of 8051.

The Program Status Word (PSW) is an 8-bit Special Function Register located at address D0H. It contains status flags and register-bank selection bits.

Bits of PSW:

  • CY: Carry flag.
  • AC: Auxiliary Carry flag.
  • F0: User-defined flag.
  • RS1 and RS0: Select register banks.
  • OV: Overflow flag.
  • P: Parity flag.
  • Bit 1: Reserved in the classic 8051.

Importance: PSW indicates the status of arithmetic operations and controls the active register bank.

10. Explain the addressing modes of 8051 with examples.

Addressing modes specify how the 8051 accesses data during instruction execution.

  1. Immediate Addressing: Data is provided directly in the instruction.
    Example: MOV A,#25H
  2. Register Addressing: Data is stored in a register.
    Example: MOV A,R2
  3. Direct Addressing: The memory address is specified directly.
    Example: MOV A,30H
  4. Register Indirect Addressing: A register contains the memory address.
    Example: MOV A,@R0
  5. Indexed Addressing: Used to access code memory using a base register and accumulator.
    Example: MOVC A,@A+DPTR
  6. Bit Addressing: Accesses a single bit.
    Example: SETB P1.0

UNIT 4 – MEMORY AND DEVICE INTERFACING

1. What is memory interfacing? Explain its need.

Memory interfacing is the process of connecting memory devices such as RAM and ROM to a microprocessor.

Need for memory interfacing:

  • To increase the available memory capacity.
  • To store program instructions.
  • To store temporary data.
  • To connect external memory devices.
  • To enable communication between the processor and memory.

Important signals:

  • Address bus.
  • Data bus.
  • Chip Select (CS).
  • Read (RD).
  • Write (WR).

Types of memory: RAM is generally used for temporary read/write storage, while ROM is used for non-volatile program storage.

2. Explain address decoding in memory interfacing.

Address decoding is the process of identifying a particular memory chip using address-bus signals.

Types of address decoding:

1. Full Address Decoding:

  • All required higher-order address bits are decoded.
  • Each memory chip receives a unique address range.
  • Prevents address duplication.

2. Partial Address Decoding:

  • Only some address bits are decoded.
  • Requires less hardware.
  • May produce multiple address locations for the same device.

Importance: Address decoding ensures that only the selected memory device responds to a processor request.

3. Explain RAM and ROM interfacing with 8085.

RAM and ROM are connected to the 8085 using address, data and control signals.

RAM Interfacing:

  • Address lines connect the processor to RAM address pins.
  • Data lines transfer data between the processor and RAM.
  • Chip Select activates the RAM device.
  • RD̅ is used for read operations.
  • WR̅ is used for write operations.

ROM Interfacing:

  • Address lines select the required memory location.
  • Data lines transfer stored instructions to the processor.
  • Chip Select enables the ROM.
  • RD̅ is used to read the stored information.

Important: The 8085 uses ALE and an external latch to separate the multiplexed lower address and data lines.

4. Explain 8255 Programmable Peripheral Interface.

The 8255 Programmable Peripheral Interface (PPI) is an interface device used to connect peripheral devices to a microprocessor. It provides 24 programmable I/O lines.

Ports:

  • Port A – 8 bits.
  • Port B – 8 bits.
  • Port C – 8 bits.

Operating modes:

  • Mode 0: Basic input/output mode.
  • Mode 1: Strobed input/output mode with handshaking.
  • Mode 2: Bidirectional data transfer mode for Port A.

Applications:

  • Keyboard interfacing.
  • Display interfacing.
  • Printer interfacing.
  • Industrial control systems.

Advantages: Provides flexible peripheral connections and reduces the need for direct processor I/O pins.

5. Explain ADC interfacing with a microprocessor.

An Analog-to-Digital Converter (ADC) converts an analog signal into digital data that can be processed by a microprocessor.

Example: ADC0808 and ADC0809 are 8-bit ADC devices with eight input channels.

Working:

  1. An analog signal is applied to the selected input channel.
  2. The required channel is selected.
  3. A conversion-start signal is given.
  4. The ADC converts the analog signal into digital form.
  5. The processor waits for the End of Conversion signal.
  6. The digital output is read by the processor.

Applications: Temperature measurement, sensor systems, digital instruments and data acquisition.

Important: An 8-bit ADC produces 256 possible digital output levels.

6. Explain DAC interfacing with a microprocessor.

A Digital-to-Analog Converter (DAC) converts digital data into an equivalent analog signal.

Example: DAC0808 is an 8-bit digital-to-analog converter that provides current output.

Working:

  1. The processor sends digital data to the DAC.
  2. The DAC receives the binary input.
  3. The DAC converts the binary value into an analog current.
  4. A suitable current-to-voltage amplifier can produce an analog voltage.

Applications:

  • Audio systems.
  • Waveform generation.
  • Motor-control systems.
  • Analog signal generation.

7. Explain keyboard and display interfacing.

Keyboard and display interfacing connects input and output devices to a microprocessor using I/O ports or an interface chip such as 8255.

Keyboard Interfacing:

  • Keys are arranged in rows and columns.
  • The processor scans the rows and columns.
  • A pressed key is identified by detecting the corresponding row and column.
  • Debouncing avoids incorrect readings caused by mechanical key contacts.

Display Interfacing:

  • Seven-segment displays are used to show numerical digits.
  • Segment patterns are supplied through I/O ports or display drivers.
  • Multiplexing can be used to control multiple digits with fewer connections.

Applications: Calculators, digital clocks, electronic instruments and control panels.

8. Differentiate serial and parallel communication.

Serial Communication: Data bits are transmitted one after another through a communication line.

  • Requires fewer wires.
  • Suitable for longer-distance communication.
  • Examples include UART, SPI and I²C.

Parallel Communication: Multiple data bits are transmitted simultaneously through separate data lines.

  • Requires more wires.
  • Transfers multiple bits at the same time.
  • Commonly used in short-distance internal connections.

Difference: Serial communication transfers data bit by bit, while parallel communication transfers multiple bits simultaneously.

UNIT 1 – 8085 MICROPROCESSOR

1. Define a microprocessor. List the features of 8085.

A microprocessor is a programmable electronic device that accepts binary data, processes it according to instructions and produces results.

Features of 8085:

  • 8-bit processor; processes 8 bits at a time.
  • 16-bit address bus; can address 64 KB of memory.
  • 8-bit data bus.
  • 40-pin IC and single +5 V supply.
  • Six general-purpose registers: B, C, D, E, H and L.
  • Contains accumulator, ALU, flag register, Program Counter and Stack Pointer.
  • Supports hardware and software interrupts.

Important: 8085 is an 8-bit processor because its data path is 8 bits wide.

2. Explain the architecture of 8085.

The architecture of 8085 is the arrangement of internal units that perform processing and control.

Main blocks:

  1. ALU: Performs arithmetic and logical operations.
  2. Accumulator: 8-bit register used to store operands and results.
  3. General-purpose registers: B, C, D, E, H and L store temporary data.
  4. Flag register: Contains Sign, Zero, Auxiliary Carry, Parity and Carry flags.
  5. Program Counter (PC): Holds the address of the next instruction.
  6. Stack Pointer (SP): Points to the top of the stack.
  7. Instruction register and decoder: Hold and decode the instruction.
  8. Timing and Control unit: Generates control signals such as RD, WR and ALE.
  9. Interrupt and serial I/O control: Handles interrupts and SID/SOD serial pins.

Working: The processor fetches an instruction, decodes it, executes it and stores the result.

3. Explain the register organization of 8085.

Registers are small, high-speed storage locations inside the processor.

  • Accumulator (A): Stores operands and ALU results.
  • B, C, D, E, H, L: Six 8-bit general-purpose registers.
  • Register pairs: BC, DE and HL can be used as 16-bit pairs. HL commonly acts as a memory pointer.
  • Flag register: Stores the five condition flags.
  • Program Counter (PC): 16-bit register containing the next instruction address.
  • Stack Pointer (SP): 16-bit register pointing to the top of the stack.
  • Instruction Register: Holds the current opcode during decoding.

Example:

MOV A,B

Copies the contents of B into A.

4. What are the addressing modes of 8085? Give examples.

An addressing mode specifies how an instruction identifies its operand.

  1. Immediate: Data is part of the instruction. MVI A,25H
  2. Register: Operand is in a register. MOV A,B
  3. Direct: Memory address is given in the instruction. LDA 2050H
  4. Register indirect: A register pair contains the memory address. MOV A,M uses HL.
  5. Implied: Operand is understood from the instruction. CMA

Important: Immediate mode specifies the value; direct mode specifies the memory address; register-indirect mode uses a register pair as a pointer.

5. Explain the flag register of 8085.

The flag register is an 8-bit status register. Five bits are used as condition flags.

  • Sign (S): Set when the most significant bit of the result is 1.
  • Zero (Z): Set when the result is 00H.
  • Auxiliary Carry (AC): Set when carry occurs from bit 3 to bit 4.
  • Parity (P): Set when the result contains an even number of 1s.
  • Carry (CY): Set when addition produces a carry out or subtraction requires a borrow.

Example: If an operation produces 00H, the Zero flag is set.

Importance: Flags are used by conditional jump instructions.

6. Explain the interrupt structure of 8085.

An interrupt is a signal that temporarily stops the normal program sequence so the processor can execute an Interrupt Service Routine (ISR).

Hardware interrupts, in priority order:

  1. TRAP: Highest priority; non-maskable and vectored.
  2. RST 7.5: Maskable, vectored and edge-triggered.
  3. RST 6.5: Maskable, vectored and level-triggered.
  4. RST 5.5: Maskable, vectored and level-triggered.
  5. INTR: Maskable and non-vectored; external hardware supplies the instruction.

Software interrupts: RST 0 to RST 7.

Advantages: Interrupts allow urgent events to be handled without continuously checking devices (polling).

7. Explain instruction cycle, machine cycle and T-state of 8085.

  • Instruction cycle: Total time required to fetch and execute one complete instruction.
  • Machine cycle: A part of an instruction cycle, such as opcode fetch, memory read, memory write or I/O operation.
  • T-state: One clock period; the smallest basic timing unit.

Relationship: One instruction cycle consists of one or more machine cycles. Each machine cycle consists of several T-states.

Example: An 8085 opcode-fetch machine cycle commonly takes 4 T-states. Memory read/write machine cycles commonly take 3 T-states.

Important: Timing depends on the instruction and the number of bus operations required.

8. Explain the functions of 8085 pins and signals.

The 8085 is a 40-pin IC. Its pins are grouped by function.

  • A8–A15: Higher-order address bus.
  • AD0–AD7: Multiplexed lower address/data bus.
  • ALE: Address Latch Enable; separates the lower address from data.
  • RD̅: Active-low read control.
  • WR̅: Active-low write control.
  • IO/M̅: Selects memory or I/O operation.
  • READY: Allows the processor to wait for slow devices.
  • HOLD / HLDA: DMA bus request and acknowledgement.
  • RESET IN̅ / RESET OUT: Reset input and reset-status output.
  • TRAP, RST 7.5, RST 6.5, RST 5.5, INTR: Interrupt inputs.
  • SID / SOD: Serial input and serial output.
  • X1, X2, CLK OUT: Clock-related pins.

Important: The bar over a signal indicates active-low operation.

UNIT 2 – 8086 MICROPROCESSOR

1. Explain the architecture of 8086.

The 8086 is a 16-bit microprocessor with a 20-bit address bus and a 16-bit data bus. It can address 1 MB of memory. Its architecture has two main units.

1. Bus Interface Unit (BIU)

  • Fetches instructions from memory.
  • Generates physical addresses.
  • Performs memory and I/O bus operations.
  • Contains CS, DS, SS and ES segment registers.
  • Contains the Instruction Pointer (IP) and a 6-byte instruction queue.

2. Execution Unit (EU)

  • Decodes and executes instructions.
  • Contains the ALU, general-purpose registers, pointer/index registers and FLAGS register.

Working: While the EU executes instructions, the BIU can fetch upcoming instructions into the queue. This overlapping is called pipelining.

2. Explain memory segmentation in 8086.

Memory segmentation divides the 8086 memory space into logical segments, each with a maximum size of 64 KB.

  • Code Segment (CS): Stores instructions.
  • Data Segment (DS): Stores data.
  • Stack Segment (SS): Stores stack data.
  • Extra Segment (ES): Additional data segment.

A logical address is written as segment:offset.

Physical address formula:

Physical address = Segment × 10H + Offset

Example: 2000H:1234H = 20000H + 1234H = 21234H.

Advantages: Provides organized memory use and allows code, data and stack areas to be addressed separately.

3. What are the addressing modes of 8086? Give examples.

An addressing mode specifies how an instruction accesses its operand.

  1. Immediate: MOV AX,1234H
  2. Register: MOV AX,BX
  3. Direct memory: MOV AL,[2000H]
  4. Register indirect: MOV AX,[BX]
  5. Based: MOV AX,[BX+04H]
  6. Indexed: MOV AX,[SI+04H]
  7. Based-indexed: MOV AX,[BX+SI]
  8. Based-indexed with displacement: MOV AX,[BX+SI+10H]
  9. Relative: JNZ LABEL
  10. Implied: CLC

Important: Effective address is calculated using base/index registers and any displacement.

4. Explain the register organization of 8086.

The 8086 contains 16-bit registers grouped according to their functions.

General-purpose registers

  • AX – Accumulator.
  • BX – Base.
  • CX – Count.
  • DX – Data.

Each can be accessed as two 8-bit registers; for example, AX is divided into AH and AL.

Pointer registers: SP (Stack Pointer), BP (Base Pointer).

Index registers: SI (Source Index), DI (Destination Index).

Segment registers: CS, DS, SS and ES.

Other registers: IP (Instruction Pointer) and FLAGS.

Example: MOV AX,BX copies BX into AX.

5. What is pipelining in 8086? Explain its advantages.

Pipelining is the technique of overlapping instruction fetching and instruction execution.

  • BIU: Fetches instruction bytes and stores them in a 6-byte queue.
  • EU: Takes instructions from the queue, decodes and executes them.

Working: While the EU executes the current instruction, the BIU fetches following instructions whenever the bus is available.

Advantages:

  • Reduces waiting time for instruction fetching.
  • Improves overall processing speed.
  • Makes better use of the bus and execution unit.

Important: A jump or branch may empty the queue because instructions must be fetched from the new address.

6. Explain minimum mode and maximum mode of 8086.

The 8086 supports two operating modes selected by the MN/MX̅ pin.

Minimum mode

  • Used in a single-processor system.
  • 8086 generates control signals directly.
  • Hardware design is simpler.

Maximum mode

  • Used in multiprocessor or coprocessor systems.
  • An external 8288 bus controller generates bus-control signals.
  • Supports bus arbitration and coordination with devices such as the 8087.

Difference: Minimum mode is intended for a single processor; maximum mode supports more complex shared-bus systems.

7. Explain the flag register of 8086.

The 8086 FLAGS register is a 16-bit register containing status and control flags.

Status flags

  • CF: Carry or borrow.
  • PF: Even parity.
  • AF: Auxiliary carry; used in BCD-related operations.
  • ZF: Set when result is zero.
  • SF: Reflects the most significant bit of the result.
  • OF: Indicates signed arithmetic overflow.

Control flags

  • TF: Enables single-step operation.
  • IF: Enables maskable interrupts.
  • DF: Controls direction in string operations.

Example: CMP AX,BX updates flags according to the subtraction but does not store the result.

8. Explain memory and I/O addressing of 8086.

Memory addressing: The 8086 has a 20-bit address bus and can address 1 MB of memory. It uses segment:offset addressing to form a physical address.

I/O addressing: The 8086 supports a separate I/O address space of up to 64 KB.

  • Direct I/O: Port number is given in the instruction. IN AL,80H
  • Indirect I/O: Port address is held in DX. OUT DX,AL

Important: Memory-mapped I/O uses memory addresses and memory instructions. Isolated I/O uses IN and OUT instructions.

UNIT 3 – 8051 MICROCONTROLLER

1. Define a microcontroller. List the features of 8051.

A microcontroller is a single integrated circuit containing a CPU, memory and input/output peripherals for controlling a specific system.

Features of the classic 8051:

  • 8-bit CPU.
  • 4 KB on-chip program ROM.
  • 128 bytes internal RAM.
  • 32 programmable I/O pins in four 8-bit ports.
  • Two 16-bit timers/counters.
  • Full-duplex serial port.
  • Five interrupt sources with two priority levels.
  • On-chip oscillator and clock circuitry.

Applications: Appliances, embedded control, instruments and automation.

Note: These memory specifications refer to the classic 8051; modern compatible chips may differ.

2. Explain the architecture of 8051.

The 8051 combines a CPU, memory, I/O ports and peripherals on one chip.

Main blocks:

  1. 8-bit CPU and ALU.
  2. Accumulator (A), B register and PSW.
  3. Four register banks, each containing R0–R7.
  4. 128-byte internal RAM in the classic 8051.
  5. 4 KB on-chip program ROM in the classic 8051.
  6. Four I/O ports: P0, P1, P2 and P3.
  7. Two 16-bit timers/counters.
  8. Serial communication port.
  9. Interrupt controller and oscillator circuit.

Working: The CPU fetches instructions from program memory, processes data and controls external devices through I/O pins.

3. Explain the memory organization of 8051.

The classic 8051 uses separate program-memory and data-memory spaces.

  • Program memory: 4 KB on-chip ROM, with provision for external program memory.
  • Internal data RAM: 128 bytes, addresses 00H–7FH.
  • Register banks: Four banks occupy 00H–1FH.
  • Bit-addressable area: 20H–2FH; individual bits can be addressed.
  • General-purpose RAM: 30H–7FH.
  • SFR space: 80H–FFH; contains control registers such as ports, timers and serial control.

Important: SFRs are not ordinary internal RAM. Memory sizes can vary in enhanced 8051 devices.

4. Explain the I/O ports of 8051.

The 8051 has four 8-bit I/O ports, providing 32 I/O lines.

  • Port 0 (P0): Open-drain port; needs external pull-up resistors when used as general-purpose I/O. It also multiplexes the low address/data bus during external memory access.
  • Port 1 (P1): General-purpose I/O.
  • Port 2 (P2): General-purpose I/O; provides the high address bus during external memory access.
  • Port 3 (P3): Has alternate functions such as RXD, TXD, INT0, INT1, T0, T1, WR̅ and RD̅.

Example: SETB P1.0 sets pin P1.0 high.

Important: Write 1 to a port latch before using a port pin as an input.

5. Explain the timers and counters in 8051.

The classic 8051 has two 16-bit timer/counter units: Timer 0 and Timer 1.

  • In timer mode, the register increments using internal machine-cycle timing.
  • In counter mode, it counts external pulses at T0 or T1.
  • TMOD selects timer/counter operation and mode.
  • TCON contains control and overflow flags.
  • Modes 0, 1, 2 and 3 are available.

Applications: Creating delays, measuring time intervals, counting external events and generating serial baud rates.

Important: A timer overflow sets its TF flag. Software or an interrupt service routine can respond to it.

6. Explain serial communication of 8051.

The 8051 has a full-duplex serial port, allowing simultaneous transmission and reception.

  • TXD (P3.1): Serial transmit pin.
  • RXD (P3.0): Serial receive pin.
  • SBUF: Data buffer used to transmit or receive a byte.
  • SCON: Serial control register; selects serial mode and contains status bits.
  • Timer 1: Commonly used to generate baud rate in classic 8051 applications.

Example: MOV SBUF,A starts transmission of the accumulator byte. TI indicates transmission completion.

Applications: Communication with computers, modules and other controllers.

7. Explain the interrupt structure of 8051.

An interrupt causes the 8051 to suspend the main program and execute an Interrupt Service Routine.

The classic 8051 has five interrupt sources:

  1. External interrupt 0 (INT0).
  2. Timer 0 overflow.
  3. External interrupt 1 (INT1).
  4. Timer 1 overflow.
  5. Serial port interrupt.

Registers:

  • IE enables or disables interrupt sources.
  • IP selects priority levels.
  • TCON and SCON contain relevant interrupt flags.

Advantages: Quick response to external events and efficient CPU use.

Important: The classic 8051 supports two priority levels: high and low.

8. Explain the register banks in 8051.

The 8051 contains four register banks, each with eight 8-bit registers R0–R7.

  • Bank 0: 00H–07H.
  • Bank 1: 08H–0FH.
  • Bank 2: 10H–17H.
  • Bank 3: 18H–1FH.

The active bank is selected by RS1 and RS0 bits in the PSW register.

Advantages: Register banks provide quick storage and can reduce the need to save and restore registers during interrupt handling.

Example: When bank 1 is selected, MOV A,R0 uses RAM location 08H as R0.

9. Explain the PSW register of 8051.

The Program Status Word (PSW) is an 8-bit special-function register at address D0H. It stores status flags and register-bank selection bits.

  • CY: Carry flag.
  • AC: Auxiliary carry.
  • F0: User flag.
  • RS1 and RS0: Select the register bank.
  • OV: Overflow flag.
  • P: Parity flag.
  • Bit 1: Reserved in the classic 8051.

Importance: PSW records arithmetic status and controls the active register bank.

Example: RS1=0 and RS0=1 selects register bank 1.

10. Explain the addressing modes of 8051 with examples.

An addressing mode specifies how an 8051 instruction accesses its operand.

  1. Immediate: MOV A,#25H – constant is in the instruction.
  2. Register: MOV A,R2 – operand is in a register.
  3. Direct: MOV A,30H – direct internal RAM/SFR address.
  4. Register indirect: MOV A,@R0 – R0 contains the RAM address.
  5. Indexed: MOVC A,@A+DPTR – reads code memory using A and DPTR.
  6. Bit addressing: SETB P1.0 – operates on one bit.

Important: # indicates immediate data; @ indicates indirect addressing.

UNIT 4 – MEMORY AND DEVICE INTERFACING

1. What is memory interfacing? Explain its need.

Memory interfacing is the process of connecting memory chips to a microprocessor so that data and instructions can be read or written.

Need for memory interfacing:

  • To expand memory capacity.
  • To connect RAM for temporary read/write storage.
  • To connect ROM/EPROM/Flash for program storage.
  • To select the correct chip using address decoding.
  • To coordinate read and write operations using control signals.

Main signals: Address bus, data bus, chip select (CS), output enable (OE), read (RD) and write (WR).

Important: Address decoding ensures that the correct memory device responds to an address.

2. Explain address decoding in memory interfacing.

Address decoding examines address-bus bits and generates a chip-select signal for a particular memory device.

Types:

  • Full decoding: All required higher address bits are decoded. It avoids address duplication but requires more hardware.
  • Partial decoding: Only some address bits are decoded. It is simpler but may cause address mirroring.

Example: A decoder uses higher address lines to select one memory chip, while lower address lines select a location inside that chip.

Importance: It ensures that the correct memory device is enabled for each address.

3. Explain the interfacing of RAM and ROM with 8085.

To interface memory with 8085, address, data and control signals must be connected correctly.

RAM connection:

  • Connect address lines to RAM address pins.
  • Connect the data bus to the processor data bus.
  • Use decoded address lines for chip select (CS).
  • Use RD̅ for output enable and WR̅ for write enable.

ROM connection:

  • Connect address and data lines similarly.
  • Use CS for chip selection.
  • Use RD̅/OE for reading; ordinary ROM is not written during normal execution.

Important: Since AD0–AD7 are multiplexed, ALE and an external latch are used to hold the lower address during a bus cycle.

4. Explain 8255 Programmable Peripheral Interface (PPI).

The 8255 PPI is a programmable interface chip used to connect peripheral devices to a microprocessor. It provides 24 programmable I/O lines.

Ports:

  • Port A: 8 bits.
  • Port B: 8 bits.
  • Port C: 8 bits; can be divided into upper and lower 4-bit groups.

Operating modes:

  • Mode 0: Simple input/output.
  • Mode 1: Strobed or handshake I/O.
  • Mode 2: Bidirectional bus mode for Port A.

Advantages: Reduces processor pin requirements and provides flexible interfacing for keyboards, displays and other peripherals.

5. Explain ADC interfacing with a microprocessor.

An Analog-to-Digital Converter (ADC) converts an analog voltage into a digital number that a microprocessor can read.

Example device: ADC0808/ADC0809 are 8-bit ADCs with multiple input channels.

Basic operation:

  1. Select the required analog input channel.

1. Translation Lookaside Buffer (TLB)

1. What is the purpose of a Translation Lookaside Buffer (TLB)?
A Translation Lookaside Buffer (TLB) is a small, high-speed cache that stores recently used virtual-page number to physical-frame number translations.

Its purpose is to speed up virtual-to-physical address translation and reduce memory access time.
Keywords: Virtual address → Physical address, page table, fast cache, address translation, TLB hit, TLB miss.
Example: If a page number is already present in the TLB, it is a TLB hit and the corresponding frame number is obtained quickly.

2. Memory Management in Linux

2. State any two features of memory management in Linux.
Important features of Linux memory management include:
  • Virtual Memory: Gives each process a large logical address space.
  • Paging: Divides virtual memory into pages and physical memory into frames.
  • Demand Paging: Loads a page into RAM only when it is required.
  • Memory Protection: Prevents one process from accessing another process's protected memory.
  • Swap Space: Allows inactive memory pages to be temporarily stored on secondary storage.
For 2 marks: Any two features are sufficient. The safest answer is virtual memory + paging.

3. Instruction Pipeline

3. List the basic stages of a typical instruction pipeline.
An instruction pipeline divides instruction execution into multiple stages so that different instructions can be processed simultaneously in different stages.

The basic stages of a typical 5-stage RISC pipeline are:
  1. IF – Instruction Fetch: Fetch the instruction from memory.
  2. ID – Instruction Decode/Register Fetch: Decode the instruction and read registers.
  3. EX – Execute: Perform ALU operation or calculate an address.
  4. MEM – Memory Access: Read/write data memory for load/store instructions.
  5. WB – Write Back: Write the result into the destination register.
IF → ID → EX → MEM → WB
Fetch → Decode → Execute → Memory → Write Back

4. Pipeline Stalling

4. What is meant by pipeline stalling?
Pipeline stalling is the temporary stopping or delaying of an instruction in the pipeline when it cannot safely proceed because of a pipeline hazard.

A bubble or NOP is inserted into the pipeline until the hazard is resolved.
Example: If an instruction needs a result that has not yet been produced by the previous instruction, the dependent instruction may be stalled for one or more clock cycles.
Keywords: Delay, hazard, bubble, NOP, extra clock cycle.

Forwarding, also called bypassing, directly transfers the result produced by one pipeline stage to another instruction that needs it, without waiting for the result to be written back to the register file.

It therefore reduces or eliminates unnecessary data-hazard stalls.

13. Structural Hazard

3. What is meant by a structural hazard in a pipeline?
A structural hazard occurs when two or more instructions in a pipeline require the same hardware resource at the same time, but the processor does not have enough resources to serve them simultaneously.
Example: If an instruction needs to access data memory while another instruction needs to fetch an instruction from the same single-port memory during the same clock cycle, a structural hazard occurs.
Solutions: Add/duplicate hardware resources, use separate instruction and data memories/caches, or stall the pipeline.
Classification: Structural hazards are one of the three major pipeline hazards: Data, Structural and Control hazards.

14. Speculative Execution

5. Define speculative execution.
Speculative execution is a processor technique in which instructions are executed before it is certain that they are actually required, usually based on a prediction such as a branch prediction.

If the prediction is correct, execution continues normally. If the prediction is wrong, the speculative results are discarded and the correct instructions are executed.

Purpose: Improve instruction-level parallelism and reduce the performance penalty caused by branches.

15. Pipeline Hazards – Classification

What are the main types of pipeline hazards?
Pipeline hazards are conditions that prevent an instruction from executing in its intended clock cycle. The three main types are:
  1. Data Hazard: Occurs because one instruction depends on the result of another.
    Example: ADD R1,R2,R3 followed by SUB R4,R1,R5.
  2. Structural Hazard: Occurs when instructions compete for the same hardware resource.
  3. Control Hazard: Occurs due to branch or jump instructions when the next instruction is uncertain.

M1 M0 Mode Description
0 0 Mode 0 13-bit timer/counter mode.

Mode 0 – 13-bit Mode

In Mode 0, the timer operates as a 13-bit register. Eight bits are obtained from THx and five bits from TLx. This mode is less commonly used.

Mode 1 – 16-bit Mode

Mode 1 uses the complete 16-bit combination of THx and TLx. It can count from 0000H to FFFFH. When the counter overflows, the overflow flag TFx becomes set.

Mode 2 – 8-bit Auto-Reload

TLx acts as an 8-bit counter while THx stores the reload value. When TLx overflows, the value stored in THx is automatically copied back into TLx. This mode is especially useful for repetitive timing and serial baud-rate generation.

Mode 3 – Split Timer Mode

Timer 0 can be divided into two independent 8-bit timer sections. This provides additional timing capability.

Example Program – Generate Delay Using Timer 0

The following is an example 8051 assembly program using Timer 0 in 16-bit Mode 1. The exact delay depends on the crystal frequency and instruction timing. 

; 8051 TIMER 0 DELAY PROGRAM
; Timer 0, Mode 1, 16-bit mode

ORG 0000H

START:
    MOV TMOD, #01H       ; Timer 0 Mode 1
    MOV TH0, #0FCH       ; Load high byte
    MOV TL0, #018H       ; Load low byte

    SETB TR0             ; Start Timer 0

WAIT:
    JNB TF0, WAIT        ; Wait until overflow

    CLR TR0              ; Stop Timer 0
    CLR TF0              ; Clear overflow flag

    SJMP START           ; Repeat

END

  6. Stop the timer.
  7. Clear the overflow flag.
  8. Repeat or continue with the required operation.

Searching and Its Types

1. Introduction

Searching is the process of finding a particular element or data from a collection of elements.

The element we want to find is called the search key.

Types of Searching

The two common searching techniques are:

  • Linear Search
  • Binary Search

2. Linear Search

Linear Search is a simple searching method in which each element is checked one by one from the beginning until the required element is found.

Example

Array:

10   25   30   45   50

Search for 45.

Compare 45 with 10 → Not found

Compare 45 with 25 → Not found

Compare 45 with 30 → Not found

Compare 45 with 45 → Found

Algorithm

  1. Start from the first element.
  2. Compare the search key with the current element.
  3. If both are equal, the element is found.
  4. Otherwise, move to the next element.
  5. Repeat until the element is found or the list ends.
  6. If the list ends, display Not Found.

Simple Pseudocode

LinearSearch(A, n, key)
    for i = 0 to n-1
        if A[i] == key
            return i
    return -1

Advantages

  • Very simple and easy to understand.
  • Works on sorted and unsorted data.
  • No special arrangement of data is required.

Disadvantages

  • Slow for large amounts of data.
  • May need to check every element.

Time Complexity

  • Best case: O(1)
  • Worst case: O(n)
  • Average case: O(n)

3. Binary Search

Binary Search is a faster searching technique that works by repeatedly dividing a sorted list into two halves.

Important: Binary search can be used only when the elements are sorted.

Example

Array:

10   20   30   40   50   60   70

Search for 60.

Middle element = 40

60 is greater than 40 → Search the right half.

Middle element of the remaining part = 60

60 is found.

Algorithm

  1. Arrange the elements in sorted order.
  2. Find the middle element.
  3. Compare the middle element with the search key.
  4. If they are equal, the element is found.
  5. If the key is smaller, search the left half.
  6. If the key is greater, search the right half.
  7. Repeat until the element is found or the search area becomes empty.

Simple Pseudocode

BinarySearch(A, n, key)
    low = 0
    high = n-1

    while low <= high
        mid = (low + high) / 2

        if A[mid] == key
            return mid
        else if key < A[mid]
            high = mid - 1
        else
            low = mid + 1

    return -1

Advantages

  • Faster than linear search.
  • Very useful for large sorted data.
  • Reduces the search area by half in every step.

Disadvantages

  • Data must be sorted.
  • Slightly more complex than linear search.

Time Complexity

  • Best case: O(1)
  • Worst case: O(log n)
  • Average case: O(log n)

4. Difference Between Linear and Binary Search

Linear Search Binary Search
Checks elements one by one Divides the list into two halves
Works on sorted and unsorted data Requires sorted data
Simple to implement Slightly more complex
Slower for large data Faster for large data
Worst case: O(n) Worst case: O(log n)

Conclusion

Searching is an important operation in Data Structures. Linear Search is simple and can be used for any list, while Binary Search is faster but requires sorted data. Therefore, binary search is preferred when the data is large and already sorted.

Sorting and Its Types

1. Introduction

Sorting is the process of arranging data in a particular order.

Usually, data is arranged in:

  • Ascending order – smallest to largest
  • Descending order – largest to smallest

Types of Sorting

Some important sorting techniques are:

  • Quick Sort
  • Merge Sort
  • Heap Sort

2. Quick Sort

Quick Sort is a sorting technique that uses the divide and conquer method.

It selects one element as a pivot and divides the remaining elements into two parts.

Steps

  1. Select an element as the pivot.
  2. Place smaller elements on the left side.
  3. Place larger elements on the right side.
  4. Apply the same process to the left and right parts.
  5. Continue until the complete array is sorted.

Example

40   20   60   10   30

Take 40 as pivot.

Smaller elements → 20   10   30

Larger elements → 60

Then sort each part.

Final result:

10   20   30   40   60

Advantages

  • Fast for large data.
  • Requires less extra memory.
  • Easy to implement using recursion.

Disadvantage

Performance can become slow if a poor pivot is selected.

Time Complexity

  • Best/Average: O(n log n)
  • Worst: O(n²)

3. Merge Sort

Merge Sort is also based on the divide and conquer method.

It divides the array into smaller parts and then merges them in sorted order.

Steps

  1. Divide the array into two halves.
  2. Continue dividing until each part contains one element.
  3. Compare the elements.
  4. Merge them in sorted order.
  5. Continue merging until one sorted array is obtained.

Example

40   20   60   10

Divide:

40 20 | 60 10

Divide again:

40 | 20 and 60 | 10

Merge:

20 40 and 10 60

Final:

10 20 40 60

Advantages

  • Gives consistent performance.
  • Suitable for large amounts of data.
  • Time complexity remains O(n log n).

Disadvantage

Requires extra memory for merging.

Time Complexity

  • Best: O(n log n)
  • Average: O(n log n)
  • Worst: O(n log n)

4. Heap Sort

Heap Sort is a sorting technique based on a heap data structure.

A heap is a special type of binary tree.

For ascending order, we generally use a Max Heap.

Steps

  1. Build a Max Heap from the given elements.
  2. Take the largest element from the root.
  3. Place it at the end of the array.
  4. Rebuild the heap.
  5. Repeat until all elements are sorted.

Example

Given:

40   10   30   20   50

After creating a Max Heap, 50 becomes the largest element.

Move 50 to the end.

Repeat the process for the remaining elements.

Final result:

10 20 30 40 50

Advantages

  • Good performance for large data.
  • Does not require much extra memory.
  • Worst-case time is predictable.

Disadvantage

More complex than simple sorting methods.

Time Complexity

  • Best: O(n log n)
  • Average: O(n log n)
  • Worst: O(n log n)

Hash function:

h(key) = key % table size

h(25) = 25 % 10 = 5

Therefore, 25 is stored at index 5.

A hash function converts a key into an index in the hash table.

Common Hash Function

h(key) = key % table size

Example:

Table size = 10

Key = 37

h(37) = 37 % 10 = 7

So, 37 is stored at index 7.

Properties of a Good Hash Function

  • It should be simple and fast.
  • It should distribute keys evenly.
  • It should reduce collisions.
  • It should always give the same index for the same key.

4. Collision

A collision occurs when two or more keys produce the same hash index.

Example

Table size = 10

h(25) = 25 % 10 = 5

h(35) = 35 % 10 = 5

Both keys get index 5.

This is called a collision.

5. Collision Resolution Techniques

Collision can be handled using different methods.

1. Separate Chaining

In separate chaining, multiple elements with the same index are stored using a linked list.

Example:

Index 5 → 25 → 35 → 45

All the elements having the same hash value are connected together.

Advantage: Simple and easy to implement.

2. Open Addressing

In open addressing, all elements are stored inside the hash table itself.

The main methods are:

  • Linear Probing
  • Quadratic Probing
  • Double Hashing

6. Linear Probing

If the required position is already occupied, we check the next position.

Example

If 25 is stored at index 5 and 35 also gets index 5:

25 → index 5

35 → index 6

If index 6 is also occupied, check index 7, and so on.

Advantage: Very simple.

Disadvantage: Can create a group of occupied positions called clustering.

7. Quadratic Probing

In quadratic probing, instead of checking the next position directly, we check positions using square values.

For example:

h(k)
h(k) + 1²
h(k) + 2²
h(k) + 3²

It helps reduce clustering compared with linear probing.

8. Double Hashing

Double hashing uses two hash functions.

The first function gives the initial position.

The second function is used to find the next position when a collision occurs.

It provides better distribution of elements.

9. Advantages of Hashing

  • Very fast searching.
  • Fast insertion and deletion.
  • Efficient for large amounts of data.
  • Average searching time is O(1).
  • Widely used in databases and computer systems.

10. Disadvantages of Hashing

  • Collisions can occur.
  • A good hash function is required.
  • Extra space may be needed.
  • Performance can become poor when many collisions occur.

11. Applications of Hashing

Hashing is used in:

  • Databases
  • Compiler symbol tables
  • Password storage
  • Caching
  • Searching
  • File systems
  • Dictionaries and maps

Conclusion

Hashing is an efficient technique for storing and retrieving data quickly. A hash function converts a key into an index. When two keys get the same index, a collision occurs. Techniques such as chaining, linear probing, quadratic probing, and double hashing are used to handle collisions.

Disjoint Set – 16 Marks

1. Introduction

A Disjoint Set is a collection of sets in which no element is common between two sets.

In simple words, disjoint sets are separate sets with no common elements.

Example

Set A = {1, 2, 3}

Set B = {4, 5, 6}

There is no common element between A and B. So, they are disjoint sets.

2. Operations of Disjoint Set

There are mainly two important operations:

1. Find

The Find operation determines which set an element belongs to.

Example:

Set A = {1, 2, 3}

Find(2) → Set A

2. Union

The Union operation combines two different sets into one set.

Example:

Set A = {1, 2}

Set B = {3, 4}

Union(A, B)

Result = {1, 2, 3, 4}

3. Representation of Disjoint Set

Disjoint sets can be represented using a tree structure.

Each set has a representative element, called the root.

       1
      / \
     2   3

       4
       |
       5

Here:

  • Root of first set = 1
  • Root of second set = 4
  • Set 1 = {1, 2, 3}
  • Set 2 = {4, 5}

4. Find Operation

The Find operation follows the parent links until it reaches the root.

Example

       1
      / \
     2   3

For Find(3):

3 → 1

So, the representative of 3 is 1.

5. Union Operation

Union combines two separate sets.

Example:

Set 1 = {1, 2}

Set 2 = {3, 4}

After Union:

Set = {1, 2, 3, 4}

The roots of the two sets are connected.

6. Union by Rank

Union by Rank is used to keep the tree short.

The smaller tree is attached under the larger tree.

Example:

Tree 1 has rank 3

Tree 2 has rank 1

Tree 2 is attached below Tree 1.

Advantage:

It reduces the height of the tree and makes the Find operation faster.

7. Path Compression

Path Compression is used during the Find operation.

It makes every node on the path point directly to the root.

Before:

4 → 3 → 2 → 1

After Find(4):

4 ─┐
3 ─┼→ 1
2 ─┘

Now the nodes can reach the root directly.

Advantage:

It makes future Find operations much faster.

8. Applications of Disjoint Sets

Disjoint sets are used in:

  • Kruskal's Minimum Spanning Tree algorithm
  • Finding connected components in a graph
  • Network connectivity
  • Image processing
  • Detecting cycles in graphs

9. Advantages

  • Simple way to manage separate groups.
  • Fast Find and Union operations.
  • Useful in graph algorithms.
  • Efficient when combined with Union by Rank and Path Compression.

10. Time Complexity

With Union by Rank + Path Compression, the operations are nearly constant time.

Find: Almost O(1)

Union: Almost O(1)

More precisely, the complexity is O(α(n)), where α(n) grows extremely slowly.

Conclusion

A Disjoint Set is used to maintain a collection of separate sets. The two main operations are Find and Union. Union by Rank and Path Compression improve its efficiency. Disjoint sets are especially important in Kruskal's algorithm and graph connectivity problems.

Page Replacement Algorithms – 16 Marks

1. Page Replacement

Page replacement is a technique used in Operating Systems when a required page is not present in main memory.

This situation is called a page fault.

If all memory frames are full, the OS selects one existing page and replaces it with the required page.

Main Page Replacement Algorithms

  • FIFO – First In First Out
  • LRU – Least Recently Used
  • OPR – Optimal Page Replacement
  • MRU – Most Recently Used

2. FIFO – First In First Out

FIFO replaces the page that entered the memory first.

Example

Pages in memory:

10 → 20 → 30

If a new page 40 arrives, 10 is removed because it came first.

10   20   30

↓

Remove 10

↓

20   30   40

Advantages

  • Simple and easy to implement.
  • Requires less overhead.

Disadvantage

May remove an important page.

Can suffer from Belady's anomaly.

3. LRU – Least Recently Used

LRU replaces the page that has not been used for the longest time.

Example

Suppose the pages were used in this order:

10 → 20 → 30 → 10 → 40

When replacement is needed, 20 may be removed because it was used least recently.

Advantages

  • Usually performs better than FIFO.
  • Uses recent page usage information.

Disadvantage

  • More difficult to implement.
  • Requires tracking page usage.

4. OPR – Optimal Page Replacement

Optimal Page Replacement replaces the page that will not be used for the longest time in the future.

Example

If memory contains:

10   20   30

and the future references show that:

10 will be used soon

20 will be used later

30 will not be used for a long time

Then 30 is replaced.

Advantages

  • Gives the minimum possible page faults.
  • Best theoretical performance.

Disadvantage

  • Future page references are not known in advance.
  • Mainly used for comparison with other algorithms.

5. MRU – Most Recently Used

MRU replaces the page that was used most recently.

Example

If pages are:

10   20   30

and 30 was accessed most recently, then 30 is replaced when a new page arrives.

Advantages

  • Simple concept.
  • Can be useful for some specific access patterns.

Disadvantage

  • Usually not suitable for general-purpose page replacement.
  • May remove a page that will be needed again soon.

6. Comparison

Algorithm Page Removed Main Advantage
FIFO Oldest page Simple
LRU Least recently used Good performance
OPR Page needed farthest in future Minimum page faults
MRU Most recently used Useful for special patterns

Conclusion

Page replacement helps the OS manage memory when a page fault occurs and all frames are occupied. FIFO removes the oldest page, LRU removes the least recently used page, OPR removes the page needed farthest in the future, and MRU removes the most recently used page.

1. DIJKSTRA'S ALGORITHM

Introduction

Dijkstra's algorithm is a shortest path algorithm used to find the shortest distance from one source vertex to all other vertices in a weighted graph.

It works when the graph contains non-negative edge weights.

Types

  • Single-source shortest path
  • Weighted graph shortest path

Basic Idea

  1. Select the source vertex.
  2. Assign distance 0 to the source and infinity to all other vertices.
  3. Select the unvisited vertex having the smallest distance.
  4. Update the distances of its neighbouring vertices.
  5. Mark the selected vertex as visited.
  6. Repeat until all required vertices are visited.

Example

2 A -------- B | | 4| |3 | | C -------- D 1 Shortest path from A to D: A → B → D Distance = 2 + 3 = 5

Applications

  • GPS and navigation systems
  • Google Maps and route finding
  • Computer networks
  • Robotics
  • Transportation systems

Advantages

  • Finds shortest paths efficiently.
  • Useful for weighted graphs.
  • Widely used in real-world routing systems.

Disadvantages

  • Does not work correctly with negative edge weights.
  • Can require more processing for very large graphs.

2. PRIM'S ALGORITHM

Introduction

Prim's algorithm is a greedy algorithm used to find the Minimum Spanning Tree (MST) of a connected weighted graph.

A Minimum Spanning Tree connects all vertices with minimum total edge weight without forming a cycle.

Steps

  1. Choose any vertex as the starting vertex.
  2. Choose the minimum-weight edge connecting the tree to an unvisited vertex.
  3. Add that edge and vertex to the tree.
  4. Repeat until all vertices are included.

Example

2 A -------- B | | 3| |4 | | C -------- D 1 Possible MST: A -- B = 2 A -- C = 3 C -- D = 1 Total cost = 6

Applications

  • Network cable design
  • Telephone networks
  • Electrical power networks
  • Road construction
  • Computer network design

Advantages

  • Simple greedy approach.
  • Works efficiently for dense graphs.
  • Produces a minimum spanning tree.

3. KRUSKAL'S ALGORITHM

Introduction

Kruskal's algorithm is a greedy algorithm used to find the Minimum Spanning Tree of a weighted graph.

Basic Idea

It sorts all edges according to their weight and repeatedly selects the smallest edge that does not create a cycle.

Steps

  1. Sort all edges in increasing order of weight.
  2. Select the smallest edge.
  3. Check whether it creates a cycle.
  4. If it does not create a cycle, add it to the MST.
  5. Continue until all vertices are connected.

Example

Edges: A-B = 2 A-C = 3 C-D = 1 B-D = 4 Sorted: C-D = 1 A-B = 2 A-C = 3 B-D = 4 Select: C-D A-B A-C MST total cost = 1 + 2 + 3 = 6

Applications

  • Network design
  • Road construction
  • Electrical networks
  • Communication networks

1. What is a Functional Dependency?

A functional dependency shows a relationship between two attributes. It means that the value of one attribute can determine the value of another attribute.

Example: Student_ID → Student_Name

Here, Student_ID determines Student_Name because each student ID belongs to only one student.

2. Define Attribute Closure.

Attribute closure is the set of all attributes that can be determined from a given set of attributes using the functional dependencies.

Example:

If A → B and B → C, then the closure of A is:

A+ = {A, B, C}

This means A can determine A, B and C.

3. What is a Minimal Cover?

A minimal cover is the smallest equivalent set of functional dependencies. It contains no unnecessary attributes or dependencies.

Example:

If we have:

A → BC

It can be divided into:

  • A → B
  • A → C

This gives a simpler set of dependencies.

4. What is Decomposition of a Relation?

Decomposition means splitting one large relation or table into two or more smaller tables to reduce redundancy and improve database design.

Example:

A Student table containing Student_ID, Student_Name and Department_Name can be divided into Student and Department tables.

5. What is a Lossless-Join Decomposition?

A decomposition is called lossless-join when the original table can be obtained exactly by joining the smaller tables.

It should not create any extra or incorrect rows.

Example: If a Student table is divided into Student and Department tables, joining them should give back the original Student information correctly.

6. What is Dependency Preservation?

Dependency preservation means that all the important functional dependencies can be checked using the decomposed tables without joining them again.

Example:

If the original table has A → B, after decomposition we should still be able to check A → B using the smaller tables.

7. Define 1NF and 2NF.

1NF (First Normal Form):

A table is in 1NF when every column contains only atomic or single values and there are no repeating groups.

Example: A student should have separate rows for different phone numbers instead of storing multiple numbers in one cell.

2NF (Second Normal Form):

A table must first be in 1NF, and every non-key attribute must depend on the complete primary key.

2NF mainly removes partial dependency.

8. Define 3NF and BCNF.

3NF (Third Normal Form):

A table is in 3NF when it is in 2NF and non-key attributes do not depend on other non-key attributes.

BCNF (Boyce-Codd Normal Form):

A table is in BCNF when, for every non-trivial functional dependency, the determinant is a superkey.

BCNF is stricter than 3NF.

9. What is a Multivalued Dependency?

A multivalued dependency occurs when one attribute determines multiple independent values of another attribute.

Example:

A student may have many hobbies and many languages.

Student →→ Hobby

Student →→ Language

The hobbies and languages are independent of each other.

10. What are Insertion, Deletion and Update Anomalies?

Anomalies are problems that occur in a poorly designed database because the same information is stored repeatedly.

  • Insertion anomaly: Difficulty in adding new information.
  • Deletion anomaly: Deleting one record may accidentally remove useful information.
  • Update anomaly: The same information must be changed in many places.
Example: If a department name is repeated in many student rows, changing the department name requires updating many rows.

11. What is a Transaction?

A transaction is a sequence of database operations treated as one logical unit of work.

A transaction should either complete successfully or should not affect the database.

Example: Transferring ₹500 from Account A to Account B involves deducting ₹500 from A and adding ₹500 to B.

12. What are the Four ACID Properties?

ACID properties ensure that database transactions are reliable.

  • Atomicity: All operations happen or none happen.
  • Consistency: The database remains correct after the transaction.
  • Isolation: Transactions do not interfere with each other.
  • Durability: Completed changes remain saved even after a failure.
Example: During a bank transfer, money should be deducted from one account and added to another. Both operations must happen correctly.

13. What is a Schedule?

A schedule is the order in which the operations of one or more transactions are executed.

Example:

T1: Read(A) → Write(A)

T2: Read(B) → Write(B)

The order of these operations forms a schedule.

14. Differentiate between Serial and Non-Serial Schedules.

Serial Schedule:

One transaction completes completely before another transaction starts.

Non-Serial Schedule:

Operations of different transactions can be mixed or interleaved.

Example:
Serial: T1 → T2
Non-Serial: T1 → T2 → T1 → T2

15. What is Serializability?

Serializability is the property that allows a non-serial schedule to produce the same result as some serial schedule.

It helps maintain the correctness of the database when transactions run at the same time.

Example: If a non-serial schedule gives the same result as T1 followed by T2, it is considered serializable.

16. What is Conflict Serializability?

Conflict serializability checks whether a schedule can be converted into a serial schedule by changing the order of non-conflicting operations.

A precedence graph is commonly used to check conflict serializability. If the graph has no cycle, the schedule is conflict serializable.

Example: If T1 and T2 perform operations that do not create a cycle in the precedence graph, the schedule is conflict serializable.

17. What is Concurrency Control?

Concurrency control is the process of managing multiple transactions running at the same time.

It prevents incorrect results and maintains database consistency.

Example: Two users trying to update the same bank account at the same time must be controlled properly.

18. What are Shared and Exclusive Locks?

Locks are used to control access to database data when multiple transactions are running.

  • Shared Lock (S): Used for reading data. Multiple transactions can usually hold a shared lock at the same time.
  • Exclusive Lock (X): Used for writing or modifying data. Other transactions cannot access the locked data in a conflicting way.
Example: T1 reads Account A → Shared Lock.
T2 wants to update Account A → Exclusive Lock.

19. What is Two-Phase Locking (2PL)?

Two-Phase Locking is a concurrency control method that uses two phases to control locks.

  • Growing Phase: The transaction can acquire locks but cannot release them.
  • Shrinking Phase: The transaction can release locks but cannot acquire new locks.
Example: First, a transaction obtains all required locks. After that, it starts releasing the locks.

A deadlock occurs when two or more transactions wait for each other indefinitely and none of them can continue.

Methods for handling deadlock:

  • Deadlock prevention
  • Deadlock detection and recovery
Example: T1 holds a lock on A and waits for B, while T2 holds B and waits for A. Both transactions keep waiting.

Two-Phase Locking (2PL) is a concurrency-control technique used in DBMS.

It controls simultaneous transactions by using locks.

The main purpose is to ensure that transactions execute in a way that is conflict-serializable.

Types of Locks

There are two major locks.

1. Shared Lock (S-lock)

Used when a transaction wants to read data.

Several transactions can hold a shared lock on the same data.

Example:

T1: Read(A)

gets:

S(A)

2. Exclusive Lock (X-lock)

Used when a transaction wants to write/update data.

Only one transaction can hold an exclusive lock.

Example:

T1: Write(A)

gets:

X(A)

Two Phases of 2PL

2PL contains two phases:

Phase 1 – Growing Phase

During this phase:

  • Transaction can acquire locks.
  • Transaction cannot release locks.

Example:

Lock-S(A)

Lock-X(B)

Phase 2 – Shrinking Phase

During this phase:

  • Transaction releases locks.
  • Transaction cannot acquire any new lock.

Example:

Unlock(A)

Unlock(B)

Important rule

Once a transaction releases its first lock, it cannot acquire another lock.

Example

Consider two transactions.

T1

Lock-X(A)
Read(A)
Write(A)

Lock-X(B)
Read(B)
Write(B)

Unlock(A)
Unlock(B)

T2

Lock-S(A)
Read(A)
Unlock(A)

T1 first obtains the required locks.

After T1 starts releasing locks, it cannot obtain any new lock.

Therefore, it follows two-phase locking.

Consider:

T1: Lock-X(A)
T1: Write(A)
T1: Unlock(A)

T2: Lock-S(A)
T2: Read(A)
T2: Unlock(A)

T2 can access A only after T1 releases it.

Therefore, the result is equivalent to:

T1 → T2

which is a serial order.

Two-phase locking divides transaction execution into a growing phase and shrinking phase. By controlling when locks can be acquired and released, it ensures conflict-serializable schedules.

8. Explain the need for concurrency control in DBMS.

Definition

Concurrency control is the process of managing multiple transactions executing at the same time without causing incorrect or inconsistent data.

In a real database, thousands of users may access the same data simultaneously.

For example:

User A → Withdraw ₹5,000
User B → Withdraw ₹3,000

Both may access the same account simultaneously.

Without concurrency control, incorrect results can occur.

Need for Concurrency Control

1. Lost Update Problem

Two transactions read the same value and update it.

Example:

Initial balance:

₹10,000

T1 reads ₹10,000.

T2 also reads ₹10,000.

T1 withdraws ₹2,000:

₹8,000

T2 withdraws ₹3,000:

₹7,000

One update may overwrite another.

This is called lost update.

2. Dirty Read

A transaction reads data that another transaction has modified but not committed.

Example:

T1 changes A = 5000
T2 reads A = 5000
T1 rolls back

Now T2 has read incorrect/uncommitted data.

3. Non-Repeatable Read

A transaction reads the same data twice but gets different values.

Example:

T1 reads A = 1000
T2 updates A = 2000
T1 reads A again = 2000

The same transaction received different values.

4. Incorrect Summary

Suppose T1 calculates total bank balance while T2 is updating accounts.

T1 may calculate using a mixture of old and new values.

Therefore, the result becomes incorrect.

Concurrency Control Techniques

1. Lock-Based Protocol

Uses locks.

Examples:

  • Shared lock
  • Exclusive lock
  • Two-phase locking

2. Timestamp-Based Protocol

Each transaction receives a timestamp.

The DBMS uses timestamps to determine the correct order of operations.

3. Optimistic Concurrency Control

Transactions execute without locking initially.

Before committing, the system checks whether conflicts occurred.

4. Multiversion Concurrency Control

Multiple versions of data are maintained.

Readers can access an appropriate version without blocking writers.

Advantages

Concurrency control:

  • Maintains consistency.
  • Prevents data corruption.
  • Prevents lost updates.
  • Controls conflicting transactions.
  • Improves database reliability.
  • Allows multiple users to work simultaneously.

Conclusion

Concurrency control is essential in multi-user DBMS environments. It allows transactions to execute concurrently while ensuring that the final database state remains correct and consistent.

9. Explain the structure and properties of a B+ Tree for a given set of keys. Illustrate searching, insertion and splitting with example.

Definition

A B+ Tree is a balanced tree data structure commonly used in DBMS indexing.

It is especially useful for:

  • Searching records
  • Range queries
  • Database indexing
  • File systems

Structure of B+ Tree

A B+ Tree has:

  1. Root node
  2. Internal nodes
  3. Leaf nodes

Important feature

Actual data/record pointers are stored only in leaf nodes.

Internal nodes mainly contain keys and pointers to child nodes.

Leaf nodes are connected using linked pointers.

Example:

              [30 | 60]
             /    |     \
            /     |      \
       [10,20] [30,40,50] [60,70,80]
          ↔          ↔           ↔

The leaf nodes are linked for fast sequential/range searching.

Properties of B+ Tree

  • It is always balanced.
  • All leaf nodes are at the same level.
  • Internal nodes contain keys and child pointers.
  • Leaf nodes contain keys and record pointers.
  • Leaf nodes are linked together.
  • Searching is efficient.
  • Supports range queries efficiently.
  • Height remains small even for large data.

Searching

Suppose the tree is:

             [30 | 60]
            /    |     \
           /     |      \
      [10,20] [30,40,50] [60,70,80]

Search for:

50

Step 1

Start from root:

[30 | 60]

50 lies between 30 and 60.

Move to middle child.

Step 2

Search:

[30,40,50]

50 is found.

Thus B+ Tree provides fast searching.

Insertion

Suppose we insert:

25

Current leaf:

[10,20]

After insertion:

[10,20,25]

If the node exceeds its maximum capacity, it must be split.

Splitting

Suppose a leaf can contain a maximum of 3 keys.

If we insert 30:

[10,20,25,30]

This exceeds the limit.

Split it:

[10,20]    [25,30]

The first key of the new right node is copied to the parent.

Parent becomes:

[25 | 60]

So:

              [25 | 60]
             /    |     \
        [10,20] [25,30] [60,70,80]

The leaf nodes remain linked.

Advantages of B+ Tree

  • Very fast searching.
  • Efficient insertion and deletion.
  • Excellent for range queries.
  • Always balanced.
  • Suitable for large databases.
  • Reduces disk I/O.
  • Leaf nodes allow sequential access.

Real-time example

Suppose a college database contains:

1,00,000 student records

An index on:

Student_ID

can use a B+ Tree.

Instead of checking every student record, the DBMS follows the tree and quickly reaches the required record.

B Tree B+ Tree

Leaf nodes may not be linked Leaf nodes are linked

Conclusion

B+ Trees are important indexing structures in DBMS because they provide fast searching, insertion, deletion and especially efficient range queries.

10. Explain the need for NoSQL databases. Discuss Key-Value Store and Document Store.

Definition

NoSQL means “Not Only SQL.”

NoSQL databases are non-relational databases designed to handle:

  • Large amounts of data
  • Unstructured/semi-structured data
  • High-speed operations
  • Distributed systems
  • Flexible data structures

Need for NoSQL

Traditional relational databases use tables with fixed schemas.

But modern applications often generate huge amounts of data.

Examples:

  • Social media
  • Online shopping
  • IoT
  • Gaming
  • Real-time applications
  • Big-data applications

The structure of this data may change frequently.

NoSQL databases provide greater flexibility.

The structure can change easily.

{
   "name": "Arun",
   "age": 20

Later, we can add:

"skills": ["JavaScript", "Python"]

without redesigning a fixed table.

2. High Scalability

NoSQL databases can scale horizontally by adding more servers.

3. High Performance

They are suitable for applications requiring fast read/write operations.

4. Handles Large Data

NoSQL is suitable for very large datasets.

5. Suitable for Distributed Systems

NoSQL databases are designed to work across multiple servers.
